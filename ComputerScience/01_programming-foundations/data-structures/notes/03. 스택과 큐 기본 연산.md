스택(Stack)은 입출구가 하나인 **후입선출(LIFO, Last-In-First-Out)** 구조이며, 큐(Queue)는 한쪽 끝에서 삽입되고 반대쪽 끝에서 삭제되는 **선입선출(FIFO, First-In-First-Out)** 구조다.

> [!IMPORTANT]
>
> - **스택**: `top` 포인터 하나로 관리하며, `push` 시 `top` 증가 후 저장, `pop` 시 데이터 반환 후 `top` 감소.
> - **큐**: `front`(출구)와 `rear`(입구) 포인터 쌍으로 관리하며, 선형 큐의 메모리 낭비 문제를 **원형 큐(Circular Queue)** 모듈로 연산(`(index + 1) % MAX`)으로 해결한다.

## 2. 연산 특성 및 복잡도 비교

<Tabs>
  <Tab label="스택 (Stack)">
    - **원리**: 한쪽 끝(Top)에서만 입출력이 일어나는 LIFO 구조.
    - **핵심 연산**: `push(x)`: $O(1)$, `pop()`:$O(1)$, `peek()`:$O(1)$.
    - **주요 활용처**: 웹 브라우저 뒤로 가기, 텍스트 편집기 실행 취소(Undo), 함수 호출 스택(Call Stack), 괄호 유효성 검사, 후위 표기법 수식 연산.
  </Tab>
  <Tab label="선형 큐 vs 원형 큐">
    - **선형 큐의 문제점**: `deQueue` 연산 시 `front`가 뒤로 이동하면서 앞 공간이 비어도 `rear == MAX - 1`이면 Overflow로 오판하는 메모리 편향 문제 발생.
    - **원형 큐의 해결책**: 모듈로 연산(`% MAX`)을 적용하여 배열의 마지막 인덱스 다음이 0번 인덱스로 순환되도록 구현.
    - **포인터 규칙**:
      - 삽입 시: `rear = (rear + 1) % MAX`
      - 삭제 시: `front = (front + 1) % MAX`
      - 포화 상태 판정: `(rear + 1) % MAX == front` (1칸을 비워두어 공백과 포화 구분)
  </Tab>
  <Tab label="덱 (Deque)">
    - **원리**: 양쪽 끝(Front, Rear) 모두에서 삽입과 삭제가 자유로운 확장형 큐.
    - **연산**: `push_front()`, `push_rear()`, `pop_front()`, `pop_rear()`.
    - **활용**: 슬라이딩 윈도우 최대/최솟값 탐색, 작업 스케줄링(Work Stealing).
  </Tab>
</Tabs>

## 3. 핵심 예외 및 경계 조건 점검

| 상황 | 원인 | 방어 코드 패턴 |
| :--- | :--- | :--- |
| **Stack Overflow** | `top >= CAPACITY - 1` 상태에서 `push()` 시도 | `if (isFull()) throw OverflowException;` |
| **Stack Underflow** | `top == -1` (공백) 상태에서 `pop()` 또는 `peek()` 시도 | `if (isEmpty()) throw UnderflowException;` |
| **Queue Overflow** | 원형 큐에서 `(rear + 1) % CAPACITY == front` 일 때 `enQueue()` | `if (isFull()) return -1;` |
| **Queue Underflow** | `front == rear` (원형 큐 공백) 일 때 `deQueue()` | `if (isEmpty()) return -1;` |

> [!WARNING]
> C/C++ 배열 기반 구현 시 경계 검사(`isEmpty`, `isFull`) 없이 인덱스에 직접 접근하면 세그멘테이션 오류(Segmentation Fault)나 가비지 값 덮어쓰기가 발생하므로 모든 연산 진입부에서 조건 분기를 수행해야 한다.
