## 2. 알고리즘 효율성 분석의 수학적 공식화 (Big-O Notation)

### 1) 점근적 상한(Asymptotic Upper Bound)의 엄밀한 정의

함수 $f(n)$과 $g(n)$에 대해, 양의 상수 $c > 0$와 $n_0 \ge 0$이 존재하여 모든 $n \ge n_0$에 대해 다음 부등식이 성립할 때 $f(n) \in \mathcal{O}(g(n))$으로 정의한다:

$$\forall n \ge n_0, \quad 0 \le f(n) \le c \cdot g(n)$$

### 2) 1부터 $n$까지의 합산 알고리즘 비교

- **방법 1: 순차 반복 누적 알고리즘**
  $$S = \sum_{i=1}^n i = 1 + 2 + \dots + n \implies \text{연산 횟수 } T(n) = n \implies \mathcal{O}(n)$$
- **방법 2: 가우스 공식(Closed-form Solution)**
  $$S_n = \frac{n(n + 1)}{2} \implies \text{연산 횟수 } T(n) = 3 \text{ 회 (곱셈, 덧셈, 나눗셈)} \implies \mathcal{O}(1)$$

## 3. 언어 번역 엔진: 컴파일러 vs 인터프리터

| 구분 | 컴파일러 (Compiler) | 인터프리터 (Interpreter) |
| :--- | :--- | :--- |
| **번역 단위** | 전체 소스코드를 일괄 분석하여 기계어 목적 파일(`.obj`, `.exe`) 생성 | 소스코드를 한 줄(Line)씩 즉시 해석하여 실행 |
| **초기 실행 지연** | 컴파일 시간 필요 (빌드 오버헤드) | 컴파일 과정 없이 즉시 실행 시작 |
| **런타임 실행 속도** | 최적화된 바이너리로 매우 빠름 ($\mathcal{O}(1)$ 런타임 오버헤드) | 매 라인 해석 오버헤드로 상대적으로 느림 |
| **대표 언어** | C, C++, Rust, Go, Fortran | Python, JavaScript, Ruby, PHP |
| **하이브리드(JIT)** | Java (JVM 바이트코드 + Just-In-Time 컴파일러), C# (.NET CLR) | |
