# [10주차] 멀티 플랫폼 배포 자동화

## 1. 프런트엔드 자동 배포 및 프리뷰 환경
코드 변경 사항을 즉시 확인하고 검증할 수 있는 환경을 구축합니다.

### 배포 및 프리뷰 설정
*   **플랫폼 활용**: GitHub Pages, Vercel, 또는 Netlify를 통한 프런트엔드 자동 배포
*   **PR 프리뷰 (Preview Deployment)**: Pull Request 생성 시 해당 변경 사항만 반영된 독립된 프리뷰 URL 자동 생성 및 결과 확인

---

## 2. Docker 기반 배포 파이프라인 설계
컨테이너 기술을 활용하여 환경에 구애받지 않는 배포 전략을 수립합니다.

### 주요 설계 전략
*   **Build-Push-Deploy**: Docker 이미지를 빌드하고 레지스트리(GHCR, Docker Hub 등)에 푸시한 뒤, 타겟 서버에서 이를 실행하는 전체 자동화 흐름 설계
*   **Multi-stage Build**: 이미지 크기를 최소화하고 보안을 강화하기 위한 멀티 스테이지 빌드 적용

---

## 3. 클라우드 플랫폼 배포 자동화 및 모니터링
실제 운영 환경(AWS, GCP 등)에 애플리케이션을 배포하고 안정성을 확보합니다.

### 클라우드 배포 실습
*   **배포 방식**: 서버리스(Lambda, Cloud Run 등) 또는 컨테이너 기반 배포 구현
*   **안정성 확보 (Reliability)**:
    *   **헬스체크 (Health Check)**: 배포 후 서비스 정상 작동 여부를 자동 확인하는 로직 포함
    *   **모니터링 (Monitoring)**: 로그 수집 및 리소스 사용량 등을 모니터링할 수 있는 기초 설정

---

## 4. 제출 및 확인 (Results)
*   **워크플로우**: `.github/workflows/deploy.yml` 파일 링크
*   **라이브 URL**: 실제 배포된 서비스의 접속 주소 및 PR 프리뷰 예시 내역

> [!important]
> **배포 안정성**: 배포 완료 직후 헬스체크 API가 실패할 경우, 즉시 이전 버전으로 롤백하거나 경고 알림을 보내는 체계를 갖추는 것이 실무에서 매우 중요합니다.
