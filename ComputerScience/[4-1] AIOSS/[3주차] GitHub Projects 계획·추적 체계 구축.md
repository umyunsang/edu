# [3주차] GitHub Projects 계획·추적 체계 구축

## 1. 칸반 기반 프로젝트 관리 체계 구축
팀의 작업 흐름을 가시화하고 효율적으로 관리하기 위해 GitHub Project를 생성합니다.

### 칸반 보드 상태(Status) 구성
*   **Backlog**: 아이디어 및 향후 진행할 모든 작업
*   **To Do**: 현재 스프린트에서 진행하기로 확정된 작업
*   **In Progress**: 현재 개발 또는 작업 중인 항목
*   **Review**: 코드 리뷰 또는 QA 대기 중인 상태
*   **Done**: 배포 및 완료가 확정된 항목

---

## 2. 백로그 및 이슈 체계 수립
실제 협업이 가능한 수준의 구체적인 작업 단위를 정의합니다.

### 구성 요소
*   **이슈(Issues)**: 10개 이상의 구체적인 작업 단위 생성
*   **템플릿(Issue Templates)**: `Bug Report`, `Feature Request` 등 목적별 입력 양식 표준화
*   **라벨(Labels) 체계**: 우선순위(Priority), 작업 유형(Type), 난이도 등 분류 체계 구축
*   **마일스톤(Milestones)**: 최소 2개 이상의 단기/중기 목표 설정 및 기한 관리

---

## 3. (선택 과제) 개발 생산성 분석
데이터 기반의 팀 성과 측정을 통해 프로세스를 개선합니다.
*   **Cycle Time**: 이슈가 시작되어 완료될 때까지 소요되는 실제 시간 분석
*   **Velocity**: 특정 기간(스프린트) 동안 팀이 처리 가능한 평균 작업량 산출
*   **Burndown Chart**: 마감 기한 대비 남은 작업량의 추이를 모니터링하여 병목 현상 파악

> [!tip]
> **스프린트 운영**: 모든 작업은 이슈로 관리되며, 이슈가 완료될 때마다 자동으로 칸반 보드의 상태가 업데이트되도록 설정하는 것을 권장합니다.
