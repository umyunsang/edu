# [8주차] 워크플로우 실행 최적화 (재사용/캐싱/조건부)

## 1. 워크플로우 모듈화 및 중복 제거
반복되는 작업을 표준화하여 유지보수 효율을 극대화합니다.

### 재사용 전략
*   **Reusable Workflows**: 여러 저장소나 프로젝트에서 공통으로 사용하는 워크플로우 단위를 분리하여 호출 방식으로 관리
*   **Composite Actions**: 여러 단계를 하나의 커스텀 액션으로 묶어 중복 코드를 제거하고 가독성 향상
*   **Matrix 확장**: 테스트 대상 버전과 OS 조합을 넓혀 광범위한 호환성 검증 수행

---

## 2. 성능 최적화 및 속도 개선
캐싱 메커니즘을 도입하여 불필요한 리소스 낭비를 줄이고 CI 실행 시간을 단축합니다.

### 실행 속도 개선 (Caching)
*   **의존성 캐싱**: `npm install`, `pip install` 등 외부 패키지 다운로드 과정을 캐싱 처리
*   **개선률 측정**: 캐싱 적용 전과 후의 실행 시간을 비교 분석하여 수치 기반의 리포트 작성
    *   예: 기존 5분 → 캐싱 후 2분 (60% 개선)

---

## 3. 선택적 실행 및 조건부 배포
불필요한 리소스 소모를 방지하기 위해 필요한 상황에서만 작업을 실행하도록 제어합니다.

### 조건부 실행 파이프라인
*   **변경 파일 감지 (Paths filter)**: 특정 디렉토리(예: `src/`, `docs/`)의 변경 여부에 따라 관련 워크플로우만 선택적 실행
*   **브랜치/PR 조건**: `main` 브랜치 병합 시에만 배포를 실행하거나, 특정 라벨이 붙은 PR에서만 테스트를 수행하는 로직 구현

---

## 4. 결과 보고 및 증빙 (GitHub Link)
*   **최적화 리포트**: 캐싱 및 모듈화 적용 전후의 성능 비교 결과
*   **워크플로우 링크**: 재사용 워크플로우 및 최적화된 YAML 파일 설정 내역

> [!tip]
> **효율적인 CI/CD**: 무조건 모든 테스트를 돌리는 것보다, 변경된 범위와 목적에 맞는 "최소한의 필수 작업"만 실행하는 것이 팀의 개발 속도를 높이는 핵심입니다.
