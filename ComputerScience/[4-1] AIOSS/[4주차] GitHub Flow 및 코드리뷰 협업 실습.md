# [4주차] GitHub Flow 및 코드리뷰 협업 실습

## 1. 브랜치 전략 및 커밋 컨벤션 적용
팀 협업의 기초가 되는 코드 관리 규칙을 수립하고 실습합니다.

### GitHub Flow 전략
*   **Feature 브랜치**: `main` 브랜치에서 분기하여 독립된 환경에서 기능 개발 진행
*   **Conventional Commits**: 메시지 형식을 표준화하여 변경 사항의 의도를 명확히 전달
    *   예: `feat: add login feature`, `fix: resolve memory leak`

---

## 2. 구조화된 코드 리뷰 수행
단순한 코드 검토를 넘어, 팀의 코드 품질을 높이기 위한 체계적인 피드백을 주고받습니다.

### 리뷰 규칙 및 피드백 태그
*   **리뷰 횟수**: 최소 3건 이상의 Pull Request(PR) 리뷰 수행
*   **피드백 태그 활용**:
    *   **[MUST]**: 반드시 수정이 필요한 치명적인 문제나 가이드라인 위반
    *   **[SHOULD]**: 수정을 권장하지만 논의가 가능한 사항
    *   **[P1~P5]**: 우선순위를 표시하여 리뷰어의 의도 전달

---

## 3. (선택 과제) 협업 자동화 및 가이드라인 구축
시스템적으로 협업의 품질을 보장할 수 있는 환경을 설정합니다.

### 주요 설정 및 문서화
*   **Pull Request 템플릿**: PR 생성 시 체크리스트 및 변경 사항 설명 양식 자동화
*   **CODEOWNERS**: 특정 파일이나 디렉토리에 대한 담당 리뷰어 자동 지정
*   **브랜치 보호 규칙**: `main` 브랜치 직접 Push 금지 및 PR 승인 필수 조건 설정
*   **협업 문서 정리**: `CONTRIBUTING.md`, `리뷰 가이드` 작성을 통해 팀 내 협업 규칙 명문화

> [!important]
> **코드 리뷰의 목적**: 잘못을 지적하는 것이 아니라, 더 나은 코드를 함께 고민하고 지식을 공유하는 과정임을 인지해야 합니다.
