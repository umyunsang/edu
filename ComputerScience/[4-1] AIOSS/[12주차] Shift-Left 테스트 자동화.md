# [12주차] Shift-Left 테스트 자동화

## 1. 단위 테스트 및 CI 통합
개발 초기 단계에서 버그를 발견하기 위해 고품질의 테스트 코드를 작성하고 자동화합니다.

### 테스트 커버리지 및 자동화
*   **커버리지 목표**: 단위 테스트(Jest, Pytest 등)를 활용하여 전체 코드의 **80% 이상** 커버리지 달성
*   **CI 통합**: 모든 Pull Request 및 Push 이벤트 발생 시 테스트를 자동 실행하고, 커버리지 리포트를 생성하도록 워크플로우 구성

---

## 2. TDD (Test-Driven Development) 실습
"실패하는 테스트 작성 -> 코드 구현 -> 리팩토링" 주기를 통해 견고한 코드를 작성합니다.

### 핵심 기능 구현
*   **방법론**: Red-Green-Refactor 사이클 엄격 준수
*   **구현 대상**: 프로젝트의 핵심 비즈니스 로직 5개 이상을 TDD 방식으로 개발

---

## 3. (선택 과제) E2E 테스트 및 레거시 리팩토링
사용자 관점에서의 최종 검증과 안전한 코드 구조 개선을 실습합니다.

### E2E (End-to-End) 테스트
*   **도구 활용**: Playwright 또는 Cypress 기반의 주요 시나리오 1개 이상 작성
*   **실패 분석**: 테스트 실패 시 디버깅을 위해 브라우저 스크린샷 또는 비디오를 GitHub Actions 아티팩트로 자동 저장

### 레거시 코드 개선
*   **안정성 검증**: 기존 레거시 코드에 테스트를 먼저 보강한 뒤 리팩토링을 수행하여 기능적 동일성 보장

---

## 4. 결과 확인 (GitHub Link)
*   **테스트 코드**: `tests/` 또는 `__tests__/` 디렉토리 내 소스 코드
*   **CI 실행 결과**: 테스트 통과 여부 및 커버리지 수치가 포함된 Actions 실행 내역

> [!important]
> **Shift-Left의 가치**: 테스트를 개발 프로세스 후반부가 아닌 초기(왼쪽)로 옮김으로써 버그 수정 비용을 획기적으로 낮출 수 있습니다.
