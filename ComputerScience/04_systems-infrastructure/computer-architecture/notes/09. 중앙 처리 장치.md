\*\*중앙 처리 장치(CPU)\*\*는 산술논리연산장치(ALU), 제어장치, 레지스터 집합으로 구성되며, 복수의 명령어를 중첩(Overlap) 실행하는 \*\*명령어 파이프라이닝(Instruction Pipelining)\*\*을 통해 클럭당 처리량(Throughput)을 극대화한다.

---

## 1. 5단계 파이프라인과 해저드 대수 공식화

### 1) 5단계 RISC 파이프라인 구조

1. **IF (Instruction Fetch)**: $\text{IR} \leftarrow M[\text{PC}], \; \text{PC} \leftarrow \text{PC} + 4$
2. **ID (Instruction Decode / Register Read)**: 명령어 디코딩 및 레지스터 파일 피연산자 인출
3. **EX (Execute / ALU Operation)**: 산술 연산 또는 유효 메모리 주소 계산
4. **MEM (Memory Access)**: 데이터 메모리 적재(Load) 또는 저장(Store)
5. **WB (Write Back)**: 연산 결과를 목적지 레지스터에 기록

### 2) 파이프라인 성능 및 가속비 (Speedup $S_k$)

$k$개 단계의 파이프라인에서 $n$개의 명령어를 클럭 주기 $\tau$로 실행할 때의 총 소요 시간:

$$T_k = (k + n - 1) \tau$$

비파이프라인 실행 시간 $T_1 = n k \tau$ 대비 가속비:

$$S_k = \frac{n k \tau}{(k + n - 1) \tau} = \frac{n k}{k + n - 1} \xrightarrow{n \to \infty} k$$

### 3) 3대 파이프라인 해저드 (Hazards)

- **구조적 해저드 (Structural Hazard)**: 동일 하드웨어 자원(명령어 메모리와 데이터 메모리)을 동시에 요구 $\implies$ 하버드 구조(Harvard Architecture, 분리 캐시)로 해결.
- **데이터 해저드 (Data Hazard, RAW)**: 이전 명령어의 결과가 WB되기 전에 후속 명령어가 ID 단계에서 참조 $\implies$ \*\*데이터 포워딩(Data Forwarding / Bypassing)\*\*으로 해결.
- **제어 해저드 (Control Hazard)**: 조건 분기 명령어에 의한 실행 흐름 변경 $\implies$ **분기 예측(Branch Prediction)** 및 분기 지연 슬롯(Delayed Branch)으로 해결.
