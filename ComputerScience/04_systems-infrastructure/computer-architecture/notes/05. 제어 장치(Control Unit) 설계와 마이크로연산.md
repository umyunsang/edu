> [!abstract] 핵심 요약
> **제어 장치(Control Unit, CU)**는 CPU 내부의 모든 레지스터 전송 및 ALU 연산 타이밍 신호(Micro-operations)를 총괄 지휘하는 지휘관이다.
> 조합 논리 게이트로 초고속 신호를 생성하는 **하드와이어드(Hardwired)** 제어(RISC 탑재)와, 제어 메모리(ROM)에 마이크로루틴을 저장하여 펌웨어 수정이 용이한 **마이크로프로그램(Microprogrammed)** 제어(CISC 탑재)의 설계 패러다임을 이해하는 것이 필수적이다.

---

## 1. 하드와이어드(Hardwired) vs 마이크로프로그램(Microprogrammed) 비교

```mermaid
flowchart TD
    ROOT["제어 장치(Control Unit) 설계 방식 비교"]
    ROOT --> HARD["1. 하드와이어드 제어 (Hardwired)<br/>• 순수 조합 논리 회로 + 시퀀스 카운터<br/>• 장점: 극도로 빠른 제어 신호 생성<br/>• 단점: 설계 변경 및 명령어 추가 곤란 (회로 재설계 필요)<br/>• 적용: 고성능 RISC 아키텍처"]
    ROOT --> MICRO["2. 마이크로프로그램 제어 (Microprogrammed)<br/>• 제어 메모리(ROM)에 마이크로코드 저장<br/>• 장점: 펌웨어 업그레이드로 명령어 추가/수정 용이<br/>• 단점: ROM 인출 지연으로 인한 상대적 속도 저하<br/>• 적용: 복잡한 ISA를 가진 CISC 아키텍처"]
```

## 2. 마이크로프로그램 제어 장치의 하드웨어 블록도

```mermaid
sequenceDiagram
    autonumber
    participant IR as 명령어 레지스터 (IR - Opcode)
    participant MUX as 주소 선택 MUX
    participant CAR as 제어 주소 레지스터 (CAR)
    participant CM as 제어 메모리 (Control Memory ROM)
    participant CBR as 제어 버퍼 레지스터 (CBR / CDR)
    participant SIG as 하드웨어 제어 신호 출력

    IR->>MUX: 매핑 로직을 통한 마이크로루틴 시작 주소 전달
    MUX->>CAR: CAR ← 다음 마이크로명령어 주소
    CAR->>CM: 제어 메모리 인출 (Fetch Micro-instruction)
    CM->>CBR: CBR ← 마이크로명령어 비트열 적재
    CBR->>SIG: ALU/레지스터 제어 비트 즉각 출력
    CBR->>MUX: 차기 주소(Next Address) 피드백 / 순차 카운터 + 1
```

## 3. 수평적(Horizontal) vs 수직적(Vertical) 마이크로명령어

| 구분 | 수평적 마이크로명령어 (Horizontal) | 수직적 마이크로명령어 (Vertical) |
| :-- | :-- | :-- |
| **비트 구성** | 1개 제어 신호당 1비트 직접 할당 ($N$비트) | $K$개 상호 배타적 신호를 $\lceil \log_2 K \rceil$ 비트로 인코딩 |
| **디코더 필요 여부** | **디코더 불필요** (신호 직접 출력) | **외부 디코더 필수** (인코딩 비트 해독) |
| **제어 속도** | **초고속** (지연 없음) | 디코딩 지연 발생 |
| **제어 메모리 폭** | 명령어 길이가 매우 길어짐 | 명령어 비트 폭이 좁아 메모리 절약 |
