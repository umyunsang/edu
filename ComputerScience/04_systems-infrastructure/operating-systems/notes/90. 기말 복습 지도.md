> [!abstract] 복습 범위
> 이 자료는 교착상태, 메모리 관리, 가상 메모리, 파일 시스템, 저장 장치와 디스크 스케줄링을 하나의 시험 복습 흐름으로 묶는다. 세부 계산의 답안이 아니라 개념 사이의 구분을 점검하는 데 사용한다.

## 복습의 큰 흐름

<Tabs>
<Tab label="자원과 대기">
교착상태는 자원을 보유한 실행 단위들이 서로의 자원을 기다리는 무한 대기 상황이다. 예방, 회피, 감지 및 복구, 무시라는 네 처리 관점이 제시된다.
</Tab>
<Tab label="주소와 페이지">
논리 주소는 프로세스별 주소 공간이고, MMU가 이를 물리 주소로 연결한다. 연속 할당, 세그먼테이션, 페이징은 할당 단위와 단편화 특성이 다르다.
</Tab>
<Tab label="디스크와 파일">
파일의 블록 배치 방식, 디스크 접근 시간의 구성, 요청 순서를 정하는 알고리즘을 함께 비교한다.
</Tab>
</Tabs>

```mermaid
flowchart LR
  A[자원 대기] --> B[메모리 주소]
  B --> C[가상 메모리]
  C --> D[파일과 디스크]
  D --> E[요청 순서 판단]
```

> [!important] 구분의 기준
> 페이징은 페이지와 프레임을 고정 크기로 나누어 외부 단편화를 피하지만, 마지막 페이지에서 내부 단편화가 생길 수 있다. 세그먼테이션은 의미 단위의 가변 크기 구성이므로 외부 단편화 가능성을 함께 확인한다.

<summary>교착상태를 볼 때의 확인 순서</summary>

1. 자원의 상호 배제가 필요한지 확인한다.
2. 보유한 채 추가 자원을 기다리는지 확인한다.
3. 선점 가능성 및 자원 요청 순서가 있는지 살핀다.
4. 안전 순서가 존재하는지를 별도로 판단한다.

</details>

## 메모리에서 저장 장치까지

요구 페이징은 필요한 일부 페이지만 물리 메모리에 올리고, 필요해진 페이지를 적재하는 방식이다. 물리 메모리에 없는 페이지 접근은 페이지 폴트로 이어진다. 수정 여부는 dirty bit로 구분하며, ==작업 집합이 메모리에 충분히 올라오지 않으면 스레싱 위험이 커진다==.

> [!note] 원문 표기 점검
> 원본에는 Deadlcok, Redudant 등 일부 철자형 표기가 보인다. 이 노트는 해당 오류를 교정한 원문이 아니며, 의미 구조만 재조직한다.

<details>
<summary>저장 장치 문제를 풀기 전 체크할 항목</summary>

- 디스크 접근 시간을 탐색, 회전 지연, 전송, 오버헤드로 나누어 본다.
- FCFS, SSTF, SCAN 계열은 요청 선택 규칙과 기아 가능성을 구분한다.
- 연속·연결·인덱스 할당은 임의 접근, 단편화, 메타데이터 비용을 함께 비교한다.

</details>

> [!success] 시험 대비 루틴
> 한 개념을 정의한 뒤, 어떤 자원 또는 주소 단위를 다루는지와 대표적인 장점·제약을 한 문장씩 말해 본다. 이후 알고리즘 문제에서는 입력 순서, 현재 상태, 다음 선택 규칙을 분리해 표기한다.

### 빠른 자가 점검

- 안전 상태와 교착상태 감지는 같은 질문인가?
- 내부 단편화와 외부 단편화는 어디에서 생기는가?
- 페이지 폴트, 스왑인, 스왑아웃의 순서를 설명할 수 있는가?
- 디스크 스케줄링에서 성능과 공정성은 어떤 방식으로 충돌하는가?
