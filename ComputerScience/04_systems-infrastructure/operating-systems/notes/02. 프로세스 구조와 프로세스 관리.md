> [!abstract] 핵심 요약
> **프로세스(Process)**는 디스크에 저장된 정적 프로그램이 메모리에 적재되어 CPU 자원을 할당받아 실행 중인 동적 인스턴스이다.
> 각 프로세스는 독립된 가상 주소 공간(**Code·Data·Heap·Stack**)을 가지며, 커널은 **PCB(Process Control Block)**를 통해 프로세스의 모든 상태와 레지스터 컨텍스트를 추적·관리한다. `fork()`를 통한 자식 생성과 `wait()` 미호출로 발생하는 좀비 프로세스의 해결, 프로세스 간 통신(**IPC**)은 시스템 프로그래밍의 핵심이다.

---

## 1. 프로세스 5상태 전이 모델 (Process Life Cycle)

```mermaid
stateDiagram-v2
    [*] --> New: 프로그램 실행 (fork)
    New --> Ready: 메모리 할당 및 준비 큐 삽입
    Ready --> Running: CPU 디스패치 (Scheduler Dispatch)
    Running --> Ready: 타이머 인터럽트 (Time Quantum 만료)
    Running --> Waiting: I/O 요청 또는 이벤트 대기
    Waiting --> Ready: I/O 완료 또는 이벤트 발생
    Running --> Terminated: 실행 완료 (exit)
    Terminated --> [*]: 부모 프로세스가 wait() 호출 후 PCB 소멸
```

---

## 2. PCB와 컨텍스트 스위칭(Context Switching)

```mermaid
sequenceDiagram
    autonumber
    participant P0 as 프로세스 P₀
    participant OS as 커널 (스케줄러)
    participant P1 as 프로세스 P₁

    P0->>OS: 타이머 인터럽트 발생 (실행 중단)
    Note over OS: 1. P₀의 레지스터, PC를 PCB₀에 저장
    Note over OS: 2. P₁의 상태를 PCB₁에서 복원
    OS-->>P1: P₁에게 CPU 할당 (실행 재개)
    Note over P0,P1: 컨텍스트 스위칭 동안 순수 CPU 연산 불가 (Overhead)
```

## 3. fork() ➔ exec() ➔ wait() ➔ exit() 제어 흐름

```mermaid
flowchart TD
    PARENT["부모 프로세스 (PID: 1000)"] -- "fork() 시스템 콜" --> FORK_RES{"반환값 (PID)"}
    FORK_RES -- "child_pid > 0" --> P_WAIT["부모: wait(&status)로 자식 종료 대기"]
    FORK_RES -- "pid == 0" --> CHILD["자식 프로세스 (PID: 1001)"]
    CHILD -- "execvp('/bin/ls', ...)" --> EXEC["새 바이너리로 주소 공간 교체 (Overlay)"]
    EXEC -- "작업 완료" --> EXIT["exit(0) 호출 ➔ 좀비(Zombie) 상태 진입"]
    EXIT --> P_WAIT
    P_WAIT --> REAP["부모가 종료 코드 수거 ➔ PCB 완전 해제"]
```
