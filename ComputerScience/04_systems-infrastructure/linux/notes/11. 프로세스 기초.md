> [!abstract]
> 프로세스는 운영체제가 실행 중인 프로그램을 관리하는 단위다.

## 핵심 구성

<Tabs>
<Tab title="실행">메모리에 적재된 작업</Tab>
<Tab title="관리">상태와 식별 정보</Tab>
<Tab title="관찰">실행 흐름 확인</Tab>
</Tabs>

```mermaid
flowchart LR
 A[입력] --> B[처리]
 B --> C[상태]
 C --> D[결과]
```

> [!important]
> 메모리에 적재된 작업와 상태와 식별 정보를 분리해 이해하면 문제 위치를 찾기 쉽다.

```html preview h=120px
<div style="font-family:system-ui,sans-serif;padding:14px;border:1px solid var(--border);border-radius:12px;background:var(--card);color:var(--foreground)"><strong>11. 프로세스 기초</strong><div style="display:flex;gap:8px;margin-top:10px"><span style="padding:8px;border:1px solid var(--border);border-radius:7px">실행</span><span style="padding:8px;border:1px solid var(--border);border-radius:7px">관리</span><span style="padding:8px;border:1px solid var(--border);border-radius:7px">관찰</span></div></div>
```

<details><summary>왜 흐름을 분리할까?</summary>

입력·처리·상태·결과를 구분하면 실패 원인과 검증 지점을 찾기 쉽다.
</details>

## 점검

==작은 예시로 먼저 입력과 결과의 연결을 확인한다.==

```html preview h=115px
<div style="font-family:system-ui,sans-serif;padding:14px;border:1px solid var(--border);border-radius:12px;background:var(--card);color:var(--foreground)">입력 <b>→</b> 처리 <b>→</b> 결과</div>
```

<details><summary>실습 전 확인</summary>

대상 환경·입력·권한과 기대 결과를 기록한다.
</details>

> [!warning]
> 환경 차이나 상태를 확인하지 않으면 같은 절차도 다른 결과를 낼 수 있다.

다음 관찰을 작업 순서에 넣는다.

> [!tip]
> 변경 하나마다 결과를 확인해 문제 범위를 좁힌다.

- 관리와 관찰는 어떻게 연결되는가?
- 무엇을 먼저 검증할 것인가?
