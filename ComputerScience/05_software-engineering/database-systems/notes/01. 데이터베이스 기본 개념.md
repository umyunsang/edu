> [!abstract] 핵심
> 데이터는 관찰·측정으로 수집한 사실이나 값이고, 정보는 의사 결정에 활용할 수 있도록 데이터를 처리한 결과다.

## 구조를 먼저 구분하기

정보 처리는 데이터에서 정보를 추출하는 과정 또는 방법이다. 데이터베이스의 필요성은 여러 사용자가 조직의 운영에 필요한 데이터를 저장하고 활용할 때 데이터와 정보의 역할을 구분하는 데서 출발한다.

```mermaid
flowchart LR
    A["요구 또는 데이터"] --> B["구조화"]
    B --> C["연산 또는 관리"]
    C --> D["제약과 통제"]
    D --> E["결과 확인"]
```

| 관점 | 핵심 질문 | 점검 방법 |
| --- | --- | --- |
| 데이터 | 관찰·측정으로 수집한 값 | 수집 단위와 출처를 기록한다 |
| 정보 | 처리되어 의사 결정에 쓰이는 결과 | 어떤 처리가 의미를 만들었는지 본다 |
| 정보 처리 | 데이터에서 정보 추출 | 입력·처리·결과를 나눈다 |

> [!note] 적용 순서
> 먼저 무엇이 원시 사실인지, 어떤 처리 뒤 의사 결정에 쓰이는지 구분한다. 그다음 저장·공유·갱신이 필요한 데이터를 데이터베이스 관점으로 정리한다.

## 세 관점

<Tabs>
<Tab label="개념">

데이터와 정보는 가공의 유무와 활용 목적에서 구분한다. 같은 값도 처리 맥락에 따라 정보가 될 수 있다.

</Tab>
<Tab label="적용">

업무에서 필요한 데이터를 먼저 식별하고, 어떤 처리를 거쳐 어떤 사용자에게 정보가 되는지 연결한다.

</Tab>
<Tab label="검증">

정보가 유용한지 판단할 때는 처리 과정·시점·사용 목적을 함께 확인한다.

</Tab>
</Tabs>
