> [!abstract] 핵심
> 데이터 모델링은 현실 세계의 데이터를 데이터베이스로 옮기는 변환 과정이며, 추상화를 통해 개념적·논리적 구조를 만든다.

## 구조를 먼저 구분하기

데이터 모델링은 데이터베이스 설계의 핵심 과정이다. 개체-관계 모델은 개념적 모델로 현실의 개체·관계·속성을 표현하고, 논리적 데이터 모델은 이를 저장과 연산에 맞는 구조로 연결한다.

```mermaid
flowchart LR
    A["요구 또는 데이터"] --> B["구조화"]
    B --> C["연산 또는 관리"]
    C --> D["제약과 통제"]
    D --> E["결과 확인"]
```

| 관점 | 핵심 질문 | 점검 방법 |
| --- | --- | --- |
| 추상화 | 현실의 복잡성을 필요한 구조로 표현 | 업무 범위를 먼저 정한다 |
| 개체·관계 | 대상과 대상 사이 연결 | 속성과 카디널리티를 확인한다 |
| 논리 모델 | 저장 가능한 구조 | 키와 제약을 정의한다 |

> [!note] 적용 순서
> 현실의 업무 문장에서 개체·속성·관계를 찾고, E-R 표현으로 검토한다. 그 뒤 관계 모델 같은 논리 구조로 옮길 때 식별자와 제약을 명시한다.

## 세 관점

<Tabs>
<Tab label="개념">

모델링은 현실을 그대로 복사하는 일이 아니라 필요한 데이터와 관계를 선택해 표현하는 일이다.

</Tab>
<Tab label="적용">

요구 문장을 개체·속성·관계로 나눈 뒤 E-R 모델을 만든다. 이후 변환 규칙으로 논리 모델을 설계한다.

</Tab>
<Tab label="검증">

업무 담당자가 모델의 의미를 검토할 수 있어야 한다. 표기법이 맞아도 요구를 빠뜨리면 좋은 모델이 아니다.

</Tab>
</Tabs>
