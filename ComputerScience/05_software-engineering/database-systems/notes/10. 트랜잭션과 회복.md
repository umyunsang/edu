> [!abstract] 핵심
> 트랜잭션은 하나의 작업에 필요한 데이터베이스 연산을 모은 논리적 작업 단위이며, 장애 회복과 일관성 관리의 기준이 된다.

## 구조를 먼저 구분하기

트랜잭션은 INSERT·DELETE·UPDATE 같은 데이터 변경 SQL의 실행을 관리하는 단위다. 여러 연산이 함께 하나의 업무를 이룰 때, 성공·실패와 회복을 트랜잭션 단위로 다루어 데이터베이스의 무결성과 일관성을 보장한다.

```mermaid
flowchart LR
    A["요구 또는 데이터"] --> B["구조화"]
    B --> C["연산 또는 관리"]
    C --> D["제약과 통제"]
    D --> E["결과 확인"]
```

| 관점 | 핵심 질문 | 점검 방법 |
| --- | --- | --- |
| 트랜잭션 | 논리적 업무 단위 | 포함할 SQL을 경계 짓는다 |
| 변경 연산 | INSERT·DELETE·UPDATE | 성공 조건과 순서를 확인한다 |
| 회복 | 장애 뒤 일관성 복원 | 완료·미완료 작업을 구분한다 |

> [!note] 적용 순서
> 업무 하나를 완료하는 데 필요한 SQL을 묶고, 성공 조건과 중단 시 되돌려야 할 상태를 정의한다. 장애 상황에서 어떤 작업이 완료·미완료인지 판단할 기준을 기록한다.

## 세 관점

<Tabs>
<Tab label="개념">

트랜잭션은 SQL 하나가 아니라 업무 수행에 필요한 연산들의 모음이다. 데이터 변경을 안전하게 관리하는 기준이다.

</Tab>
<Tab label="적용">

주문처럼 여러 변경이 함께 성공해야 하는 업무를 트랜잭션으로 정의한다. 작업 경계를 코드와 설계에 명시한다.

</Tab>
<Tab label="검증">

장애를 가정해 중간 상태가 남았을 때 무엇을 복구해야 하는지 확인한다. 무결성과 일관성의 기준을 먼저 정한다.

</Tab>
</Tabs>
