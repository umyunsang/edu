> [!abstract] 핵심
> 데이터베이스 보안은 허가된 사용자만 필요한 범위에서 접근하도록 통제하며, 물리·권한·운영 관리가 함께 작동한다.

## 구조를 먼저 구분하기

데이터베이스 보안의 목표는 조직에서 허가한 사용자만 접근하도록 통제하는 것이다. 물리적 환경의 위험으로부터 보호하고, 계정·권한으로 사용 범위와 작업을 제한하며, 운영 관리에서 제약조건을 통해 데이터 무결성을 유지한다. 역할은 권한 관리를 묶어 수행하는 방법이다.

```mermaid
flowchart LR
    A["요구 또는 데이터"] --> B["구조화"]
    B --> C["연산 또는 관리"]
    C --> D["제약과 통제"]
    D --> E["결과 확인"]
```

| 관점 | 핵심 질문 | 점검 방법 |
| --- | --- | --- |
| 물리 보안 | 재해 등 물리 손실 보호 | 저장 환경 위험을 확인한다 |
| 권한 관리 | 사용자별 접근·작업 제한 | 부여·취소 범위를 기록한다 |
| 운영 관리 | 제약으로 무결성 유지 | 권한 안의 사용도 검토한다 |

> [!note] 적용 순서
> 보호할 데이터와 사용자 역할을 식별한 뒤, 역할별 허용 작업을 정의한다. 권한 부여·취소 절차와 물리·운영 통제 조건을 별도로 점검한다.

## 세 관점

<Tabs>
<Tab label="개념">

보안은 로그인 여부만이 아니라 물리적 보호, 권한 통제, 운영 중 무결성 관리의 조합이다.

</Tab>
<Tab label="적용">

사용자를 개별 권한 목록으로만 관리하지 않고 역할로 묶어 공통 권한을 관리한다. 변경·취소 절차도 둔다.

</Tab>
<Tab label="검증">

허용된 사용자가 권한 범위 안에서 수행한 작업도 제약을 위반하지 않는지 확인한다. 접근 기록과 정책을 분리한다.

</Tab>
</Tabs>
