> [!abstract] 핵심
> DBMS는 파일 시스템의 중복·종속·공유·보안·회복 한계를 줄이기 위해 데이터를 통합적으로 관리하는 소프트웨어다.

## 구조를 먼저 구분하기

파일 시스템은 응용 프로그램별로 필요한 데이터를 별도 파일로 관리한다. 이 방식은 같은 데이터의 중복 저장, 데이터 파일 종속, 동시 공유·보안·회복의 부족을 낳을 수 있다. DBMS는 이런 관리 기능을 한 시스템에서 제공한다.

```mermaid
flowchart LR
    A["요구 또는 데이터"] --> B["구조화"]
    B --> C["연산 또는 관리"]
    C --> D["제약과 통제"]
    D --> E["결과 확인"]
```

| 관점 | 핵심 질문 | 점검 방법 |
| --- | --- | --- |
| 중복성 | 같은 데이터가 여러 파일에 존재 | 갱신 뒤 일관성을 확인한다 |
| 종속성 | 응용이 파일 구조에 묶임 | 구조 변경의 영향을 본다 |
| 공유·통제 | 여러 사용자가 접근 | 권한·동시성·회복 요구를 정한다 |

> [!note] 적용 순서
> 파일 단위로 흩어진 데이터와 공통으로 관리할 데이터를 구분한다. 중복·일관성·공유·보안·회복 요구를 목록화해 DBMS 기능과 연결한다.

## 세 관점

<Tabs>
<Tab label="개념">

DBMS의 등장 배경은 단지 저장 공간이 아니라 중복과 종속으로 인한 관리 문제다.

</Tab>
<Tab label="적용">

업무별 파일을 나열한 뒤 공통 데이터와 갱신 지점을 찾는다. 그 요구를 DBMS의 관리 기능으로 옮긴다.

</Tab>
<Tab label="검증">

DBMS 도입 뒤에도 데이터 모델·권한·백업 같은 설계가 없으면 문제가 자동으로 사라지지 않는다.

</Tab>
</Tabs>
