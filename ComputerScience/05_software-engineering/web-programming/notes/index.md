* [05. 웹 보안과 세션·인증 아키텍처 - 쿠키(HttpOnly·Secure) vs 세션(JSESSIONID), JWT와 토큰 기반 인증](./05.%20%EC%9B%B9%20%EB%B3%B4%EC%95%88%EA%B3%BC%20%EC%84%B8%EC%85%98%C2%B7%EC%9D%B8%EC%A6%9D%20%EC%95%84%ED%82%A4%ED%85%8D%EC%B2%98%20-%20%EC%BF%A0%ED%82%A4%28HttpOnly%C2%B7Secure%29%20vs%20%EC%84%B8%EC%85%98%28JSESSIONID%29%2C%20JWT%EC%99%80%20%ED%86%A0%ED%81%B0%20%EA%B8%B0%EB%B0%98%20%EC%9D%B8%EC%A6%9D.md) - HTTP 무상태(Stateless) 한계를 극복하는 상태 유지 2대 기법, 클라이언트 브라우저에 저장되는 쿠키(Cookie - HttpOnly: XSS 방어, Secure: HTTPS 강제, SameSite: CSRF 방어), 서버 메모리에 상태를 저장하는 세션(Session - JSESSIONID 발급 및 스케일아웃 시 세션 불일치 해소: Sticky Session vs Redis Session Clustering), 마이크로서비스(MSA)를 위한 무상태 토큰 기반 인증 JWT(JSON Web Token - Header, Payload, Signature 암호화 검증), 그리고 Spring Security 필터 체인 아키텍처를 인터랙티브 세션 vs JWT 인증 비교기로 학습한다.
