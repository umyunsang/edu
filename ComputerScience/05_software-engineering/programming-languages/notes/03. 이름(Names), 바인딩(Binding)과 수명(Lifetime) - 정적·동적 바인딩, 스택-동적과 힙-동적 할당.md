> [!abstract] 핵심 요약
> **바인딩(Binding)**이란 속성과 엔터티, 연산과 기호 간의 연관 관계를 맺는 행위이며, 이 바인딩이 일어나는 시점(**Binding Time**)에 따라 시스템의 효율성과 유연성이 결정된다.
> 실행 전 컴파일 시점에 타입과 주소가 고정되는 **정적 바인딩**은 고속 실행과 정적 검증을 제공하며, 런타임에 바인딩되는 **동적 바인딩**은 뛰어난 유연성을 제공하지만 실행 오버헤드를 수반한다. 변수의 메모리 공간 유지 기간을 뜻하는 **수명(Lifetime)**은 정적, 스택-동적(지역변수), 힙-동적(동적 객체)으로 체계화된다.

## 1. 바인딩 시간(Binding Time) 6대 분류

```mermaid
flowchart LR
    L_DESIGN["1. 언어 설계 시점<br/>(연산자 기호 '+'의 의미 정의)"] --> L_IMPL["2. 언어 구현 시점<br/>(정수형 int의 비트 크기 결정)"]
    L_IMPL --> COMPILE["3. 컴파일 시점<br/>(변수의 정적 타입 및 크기 바인딩)"]
    COMPILE --> LINK_LOAD["4. 링크/로드 시점<br/>(정적 전역 변수의 물리 주소 바인딩)"]
    LINK_LOAD --> RUNTIME["5. 런타임 (실행 시점)<br/>(지역 변수 스택 프레임 주소 및 값 바인딩)"]
```

## 2. 변수의 4대 메모리 수명(Lifetime) 모델

| 수명 범주 | 메모리 바인딩 시점 | 해제 시점 | 장점 및 대표 예시 | 단점 |
| :-- | :-- | :-- | :-- | :-- |
| **정적 (Static)** | 프로그램 실행 시작 전 (Data/BSS 영역) | 프로그램 종료 시 | 접근 속도 최고, 전역 상태 보존 (`static int count;`) | 재귀 호출 지원 불가, 메모리 낭비 |
| **스택-동적 (Stack-dynamic)** | 함수 선언문 도달 시 (Call Stack) | 함수 반환 시 (Return) | 재귀 함수 가능, 메모리 공간 재활용 (함수 지역 변수) | 할당/해제 오버헤드, 간접 주소 지정 |
| **명시적 힙-동적 (Explicit Heap)** | 명시적 명령 실행 시 (Heap) | 프로그래머 명령/GC에 의해 해제 | 런타임 가변 크기 구조 지원 (`malloc()`, `new`) | 포인터 오류, 메모리 누수, 할당 비용 |
| **묵시적 힙-동적 (Implicit Heap)** | 변수에 값이 할당될 때마다 묵시적 할당 | 변수에 다른 타입 값 재할당 시 | 최고 수준의 유연성 (JS, Python 변수) | 모든 속성의 동적 관리로 실행 속도 저하 |
