> [!abstract] 핵심
> 오버피팅은 학습 데이터에는 과도하게 맞지만 그 밖의 데이터에는 대응하지 못하는 상태이며, 모델 복잡도와 데이터 양을 함께 살펴야 한다.

## 문제를 학습 흐름으로 바꾸기

과소적합·적절한 적합·오버피팅은 학습과 시험 데이터에서의 성능 차이로 구분할 수 있다. 매개변수가 많은 모델이나 적은 학습 데이터는 과도한 적합이 생기기 쉬운 조건이다. 핵심은 훈련 성능 하나가 아니라 보지 않은 데이터에서의 일반화다.

```mermaid
flowchart LR
    A["입력 또는 목표"] --> B["표현과 준비"]
    B --> C["모델 또는 규칙"]
    C --> D["학습 또는 생성"]
    D --> E["검증과 해석"]
```

| 관점 | 확인할 질문 | 학습할 때의 점검 |
| --- | --- | --- |
| 학습 성능 | 훈련 자료에 대한 맞춤 정도 | 손실과 정확도를 기록한다 |
| 검증 성능 | 새 자료에 대한 대응 | 학습 지표와 차이를 비교한다 |
| 모델 복잡도 | 매개변수의 수와 표현력 | 데이터 양과 함께 해석한다 |

> [!note] 흐름
> 학습과 검증 지표를 같은 epoch 축에서 기록하고, 둘 사이 간격이 커지는 지점을 확인한다. 모델 크기·데이터 양·학습 반복을 한 조건씩 조절해 어떤 요인이 차이를 만드는지 본다.

## 관점을 나누어 보기

<Tabs>
<Tab label="개념">

오버피팅은 학습 성능이 좋다는 사실만으로 판단하지 않는다. 학습에 쓰지 않은 자료에서의 성능이 핵심이다.

</Tab>
<Tab label="실행">

동일한 데이터 분할을 유지한 채 모델 크기나 epoch를 바꾼다. 그때 학습·검증 곡선을 함께 저장한다.

</Tab>
<Tab label="검증">

검증 성능이 나빠지는 구간은 데이터 증식·규제·조기 종료 같은 대응을 검토할 신호다.

</Tab>
</Tabs>

<details>
<summary>복습 질문</summary>

학습 손실은 계속 줄어드는데 검증 성능이 나빠질 때 무엇을 의심해야 하는가? 매개변수 수와 데이터 양은 왜 함께 봐야 하는가?

</details>

> [!tip] 학습 전략
> 목표, 입력, 평가 기준을 한 문장으로 연결해 본다. 한 번에 여러 조건을 바꾸지 말고 결과 변화의 원인을 기록한다.
> [!warning] 해석 주의
> 한 번의 데이터 분할에서만 보인 차이로 일반화 성능을 단정하지 않는다. 분할과 평가 조건을 기록한다.
