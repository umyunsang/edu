## Ch5. Stereo Vision 고급 정리

Ch5는 중간고사에서 다룬 핀홀/깊이/시차/epipolar/COLMAP을 brief bridge로 짧게 연결한 뒤, 기말 범위의 핵심인 Block matching 이후 dense stereo 방법 비교에 집중한다.

### 0. brief bridge: 중간고사 overlap 압축

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.2-21, `중간고사_컴퓨터비전_정밀분석_정리.md` §10-11

#### 개념 설명

스테레오 비전은 두 카메라에서 같은 3D 점이 영상에 맺힌 위치 차이, 즉 disparity를 이용해 깊이를 추정한다. 핀홀 모델, depth ambiguity, epipolar constraint, rectification, COLMAP의 SfM/MVS 흐름은 이미 중간고사 정리의 사전 지식이므로 여기서는 새 dense stereo 알고리즘을 이해하기 위한 연결만 남긴다.

- 핀홀 투영: $x=fX/Z+p_x$, $y=fY/Z+p_y$.
- 단안 카메라의 depth ambiguity: 한 장의 영상만으로 절대 깊이를 고정하기 어렵다.
- disparity: rectified stereo에서 좌우 영상의 같은 점이 주로 같은 행에서 $x$ 방향으로 어긋난 양.
- 깊이 공식: $\displaystyle Z=\frac{fB}{d}$.
- 비례관계: $f$ 또는 $B$가 커지면 같은 $d$에서 추정 깊이 $Z$가 커지고, $d$가 커지면 $Z$는 작아진다.
- epipolar/rectification: 대응점 탐색을 2D 영역에서 같은 scanline의 1D search range로 줄인다.
- COLMAP: SfM으로 카메라 자세와 sparse point를 얻고 MVS로 dense reconstruction을 만든다는 큰 흐름만 LMS의 NeRF/3DGS 전처리와 연결한다.

#### likely exam questions

- 5지선다형: $Z=fB/d$에서 $d$가 증가할 때 깊이 변화로 맞는 설명을 고르는 형태.
- 4지선다형: epipolar constraint가 줄여 주는 탐색 차원을 고르는 형태.
- 함정: 이 bridge 영역은 고급 Ch5의 전개를 위한 전제이지, 핀홀 모델 전체를 다시 설명하는 파트가 아니다.

### 1. Local stereo: Block matching

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.23-35

#### 개념 설명

Block matching은 왼쪽 영상의 한 픽셀 주변 작은 window/block을 잡고, 오른쪽 영상의 같은 scanline에서 disparity 후보 $d$만큼 이동한 block들과 비교해 가장 잘 맞는 후보를 고르는 local stereo 방법이다.

- 입력 단위: 단일 픽셀이 아니라 주변 window/block.
- 탐색 위치: rectification을 전제로 같은 행의 search range 안.
- 출력: 각 픽셀의 최적 disparity. 모든 픽셀에 대해 반복하면 disparity map이 된다.
- 대표 matching cost: SAD/SSD/NCC.

#### formula / parameters

왼쪽 block $W_L(x,y)$와 오른쪽 후보 block $W_R(x-d,y)$의 비용 $C(x,y,d)$를 계산하고, 비용이 가장 낮거나 유사도가 가장 높은 $d$를 선택한다.

$$
d^*(x,y)=\arg\min_d C(x,y,d)
$$

주요 파라미터는 block size와 search range다.

| 파라미터 | 의미 | 커질 때 | 작아질 때 |
| --- | --- | --- | --- |
| block size | 비교에 사용할 주변 window 크기 | 노이즈에 강하고 textureless 영역에서 안정적일 수 있으나 depth edge가 뭉개짐 | 경계 보존은 좋지만 노이즈와 잘못된 매칭에 취약 |
| search range | 검사할 disparity 후보 범위 | 가까운 물체와 큰 disparity를 찾을 수 있으나 계산량과 반복 패턴 오매칭 가능성 증가 | 빠르지만 실제 disparity가 범위 밖이면 실패 |

#### SAD/SSD/NCC

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.23-29

| 비용/유사도 | 핵심 정의 | 값 해석 | 시험 함정 |
| --- | --- | --- | --- |
| SAD/SSD/NCC | 세 비용군을 한 번에 비교해 외우기 | SAD/SSD는 낮을수록 좋고, NCC는 높을수록 좋다 | NCC를 SAD처럼 최소화한다고 외우면 틀리기 쉽다 |
| SAD, Sum of Absolute Difference | 대응 픽셀 차이의 절댓값 합 | 작을수록 두 block이 유사 | 계산량이 비교적 작다 |
| SSD, Sum of Squared Difference | 대응 픽셀 차이의 제곱합 | 작을수록 두 block이 유사 | 큰 오차와 노이즈에 더 큰 penalty |
| NCC, Normalized Cross Correlation | 두 block의 정규화 상관계수 | $-1 \le NCC \le 1$, 1에 가까울수록 완전 일치 | 평균/분산 차이를 정규화하므로 단순 밝기 차이에 SAD/SSD보다 덜 민감 |

대표식의 의미만 잡으면 된다.

$$
SAD(d)=\sum_{(i,j)\in W}\left|I_L(x+i,y+j)-I_R(x-d+i,y+j)\right|
$$

$$
SSD(d)=\sum_{(i,j)\in W}\left(I_L(x+i,y+j)-I_R(x-d+i,y+j)\right)^2
$$

$$
NCC(d)=
\frac{\sum_{(i,j)\in W}(L_{ij}-\bar L)(R_{ij}(d)-\bar R_d)}
{\sqrt{\sum_{(i,j)\in W}(L_{ij}-\bar L)^2}\sqrt{\sum_{(i,j)\in W}(R_{ij}(d)-\bar R_d)^2}}
$$

#### proportional relationships / comparisons

- block size가 너무 크면 서로 다른 깊이의 픽셀이 한 window에 섞여 object boundary가 흐려진다.
- block size가 너무 작으면 한 픽셀 노이즈, 조명 변화, 반복 패턴에 쉽게 흔들린다.
- search range가 넓을수록 계산량은 대체로 후보 disparity 수에 비례해 증가한다.
- SAD/SSD는 absolute intensity 차이에 기반하므로 조명 변화가 있으면 비용이 왜곡될 수 있다.
- NCC는 correlation을 보므로 밝기 scale 차이에 상대적으로 강하지만 계산이 더 무겁다.

#### error classes

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.30-35

| 오류 상황 | 왜 어려운가 | typical wrong answer |
| --- | --- | --- |
| textureless region | 단색 벽, 하늘처럼 모든 block이 비슷해 cost 차이가 작다 | block matching은 항상 dense disparity를 정확히 준다 |
| repetitive patterns | 창문 격자, 체커보드처럼 같은 모양이 반복되어 여러 후보가 비슷하다 | search range를 넓히면 항상 해결된다 |
| occlusion | 한쪽 카메라에는 보이지만 다른 쪽에는 없는 영역은 대응 block 자체가 없다 | SAD/SSD/NCC 중 하나만 바꾸면 완전히 해결된다 |

#### likely exam questions

- 5지선다형: SAD, SSD, NCC의 값 해석과 노이즈 민감도를 비교하는 형태.
- 5지선다형: block size를 키웠을 때 경계와 노이즈에 생기는 trade-off를 고르는 형태.
- 4지선다형: textureless/repetitive/occlusion 중 block matching이 실패하기 쉬운 원인을 매칭하는 형태.

### 2. Global matching: energy minimization

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.45-53

#### 개념 설명

Global matching은 각 픽셀을 독립적으로 맞추는 대신, 전체 disparity map $d$가 좋은지 하나의 에너지로 평가하고 그 에너지를 최소화하는 방식이다. 핵심은 data term과 smoothness term의 균형이다.

$$
E(d)=E_{data}(d)+\lambda E_{smooth}(d)
$$

- $E_{data}(d)$: 왼쪽 픽셀과 오른쪽 후보 픽셀이 얼마나 잘 맞는지 측정한다. 예를 들어 각 픽셀의 SAD cost를 더할 수 있다.
- $E_{smooth}(d)$: 인접 픽셀의 disparity가 비슷해야 한다는 제약이다. 깊이 경계가 아닌 곳에서는 주변 픽셀 깊이가 대체로 부드럽다는 관찰을 사용한다.
- $\lambda$: data fidelity와 smoothness의 상대 비중을 조절하는 계수다.

#### smoothness term and trade-off

| 조절 방향 | 결과 | 함정 |
| --- | --- | --- |
| data term 위주 | 원 영상의 local matching cost를 강하게 따른다 | textureless/repetitive 영역의 noisy disparity가 남는다 |
| smoothness term 위주 | 깊이지도가 매끄럽고 구멍이 줄어든다 | 실제 depth discontinuity까지 평평하게 만들 수 있다 |
| 균형 | local evidence와 주변 일관성을 동시에 사용 | 완전한 전역 최적해는 현실적으로 어렵고 근사 최적화가 필요하다 |

smoothness penalty의 대표 직관은 두 가지다.

- Potts형: $d_p \ne d_q$이면 일정 penalty를 준다.
- 차이 기반: $|d_p-d_q|$가 클수록 더 큰 penalty를 준다.

#### GraphCut / dynamic programming / cost volume

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.49-53

| 방법 | 핵심 아이디어 | 장점 | 한계/함정 |
| --- | --- | --- | --- |
| GraphCut | 픽셀과 disparity 후보를 graph로 모델링하고 minimum cut으로 2D 최적화 | 2D 인접관계를 직접 반영하므로 block matching보다 global | 비용과 모델링이 무겁고, 모든 문제를 정확히 풀 수 있다는 뜻은 아니다 |
| dynamic programming | scanline마다 matching cost table을 만들고 1D 최적화 | 한 행 단위에서는 효율적 | 행 사이 일관성이 약해 줄무늬나 라인 간 불일치가 생길 수 있다 |
| cost volume | 영상 크기 $W \times H$와 disparity 후보 수 $D$에 대해 $W \times H \times D$ 비용을 저장 | classical matching과 deep stereo를 잇는 공통 구조 | $D$가 커지면 메모리와 계산량이 함께 증가 |

cost volume은 각 위치 $(x,y)$와 후보 disparity $d$에 대한 matching cost $C(x,y,d)$를 모은 3차원 구조다. GraphCut에서는 이 volume을 graph 최적화의 비용으로 쓰고, RAFT-Stereo 같은 deep stereo에서는 correlation pyramid의 기반으로 확장한다.

#### likely exam questions

- 5지선다형: $E_{data}$와 $E_{smooth}$의 역할을 고르는 형태.
- 5지선다형: GraphCut, dynamic programming, SGBM 중 2D 최적화/1D scanline/다방향 DP를 구분하는 형태.
- 4지선다형: $W \times H \times D$ cost volume에서 $D$가 뜻하는 것을 고르는 형태.

### 3. Semi-global matching: SGBM

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.56-59

#### 개념 설명

SGBM, Semi-Global Block Matching은 block matching의 속도와 global matching의 정확도 사이를 노리는 절충 방식이다. 한 scanline만 보는 dynamic programming은 행 사이 불일치와 가로 줄무늬가 생길 수 있으므로, SGBM은 여러 방향에서 경로 비용을 계산해 합산한다.

- 일반 DP: 한 line 또는 한 방향의 최적화.
- SGBM: 8방향 또는 16방향의 DP 경로 비용을 모아 semi-global하게 disparity를 선택.
- 효과: 한 방향 DP의 stripe artifact를 줄이고, 완전 global method보다 계산 부담을 낮춘다.

#### formula / parameters

SGBM의 핵심은 각 방향 $r$에서 누적 경로 비용 $L_r(p,d)$를 계산하고, 여러 방향 비용을 합쳐 최종 disparity를 고르는 것이다.

$$
S(p,d)=\sum_r L_r(p,d)
$$

$$
d^*(p)=\arg\min_d S(p,d)
$$

smoothness term은 주변 픽셀과 disparity가 급격히 달라질 때 penalty를 준다.

- 작은 disparity 변화: 작은 penalty로 허용한다.
- 큰 disparity jump: 더 큰 penalty를 주어 불필요한 깊이 흔들림을 막는다.
- 실제 깊이 경계: 너무 강한 smoothness는 경계를 흐릴 수 있으므로 data term과 균형이 필요하다.

#### comparisons

| 구분 | Block matching | dynamic programming | SGBM | GraphCut |
| --- | --- | --- | --- | --- |
| 범위 | local window | line-level | multi-direction semi-global | 2D global graph |
| 속도 | 빠름 | 비교적 빠름 | 중간 | 상대적으로 무거움 |
| 줄무늬 문제 | local noise 가능 | line 간 불일치 가능 | 여러 방향 통합으로 완화 | 2D smoothness로 완화 |
| 시험 키워드 | block size, search range | scanline, 1D | 8/16 directions, path cost, smoothness term | minimum cut, cost volume |

#### likely exam questions

- 5지선다형: SGBM이 dynamic programming의 줄무늬 문제를 줄이는 이유를 고르는 형태.
- 4지선다형: SGBM의 "Semi-Global"이 완전 전역 최적화가 아니라 여러 방향 DP 합산임을 묻는 형태.
- 5지선다형: smoothness term을 너무 크게 둘 때 실제 depth edge가 어떻게 되는지 고르는 형태.

### 4. Robust matching cost: Census transform

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.60-61

#### 개념 설명

Census transform은 픽셀의 절대 밝기값을 그대로 비교하지 않고, 중심 픽셀과 주변 픽셀의 상대 밝기 순서를 bit pattern으로 바꾸는 방법이다. 두 block의 bit string을 XOR한 뒤 Hamming distance가 가장 작은 후보를 더 좋은 match로 본다.

#### formula / parameters

- 기준 픽셀보다 주변 픽셀이 밝으면 1, 어두우면 0으로 기록한다.
- 주변 순서를 고정해 bit string을 만든다.
- 두 bit string의 차이는 Hamming distance로 측정한다.

$$
C_{census}(d)=Hamming\left(T_L(x,y),T_R(x-d,y)\right)
$$

#### proportional relationships / comparisons

| 비교 | SAD/SSD | Census transform |
| --- | --- | --- |
| 사용하는 정보 | 절대 밝기 차이 | 중심 대비 주변 밝기의 상대 순서 |
| 조명 변화 | 밝기 offset/scale에 취약할 수 있음 | 전체적인 밝기 변화에는 상대적으로 안정 |
| 구조 정보 | 픽셀 값 차이 중심 | 주변 패턴 구조를 bit string으로 압축 |
| 거리 측정 | 절댓값/제곱 차이 | XOR + Hamming distance |

> [!warning] 함정
> Census가 모든 문제를 해결하는 것은 아니다. 상대 밝기 순서를 쓰므로 조명 변화에는 강하지만, occlusion처럼 대응점이 존재하지 않는 문제는 비용 함수만 바꿔서 완전히 해결할 수 없다.

#### likely exam questions

- 5지선다형: Census transform이 조명 변화에 강한 이유를 고르는 형태.
- 4지선다형: XOR와 Hamming distance가 Census matching에서 하는 역할을 고르는 형태.

### 5. Deep stereo pipeline

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.62-74

#### 개념 설명

Deep stereo는 좌우 영상을 직접 hand-crafted cost로만 비교하지 않고, neural network가 feature map을 만들고 cost volume을 구성한 뒤, 비용을 정제해 disparity를 추정하는 방법이다. 강의자료의 기본 순서는 다음 네 단계다.

1. Feature extraction: 좌우 이미지에서 correlation 계산에 쓸 feature map을 만든다.
2. Cost volume 생성: 각 픽셀 또는 feature 위치와 disparity 후보의 matching cost/correlation을 모은다.
3. Cost aggregation/refinement: 초기 cost volume의 noisy match를 3D CNN 또는 recurrent update로 정제한다.
4. Disparity estimation: 정제된 cost에서 disparity를 직접 고르거나 확률적 기대값으로 구한다.

#### cost volume

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.66-73

Classical stereo에서 cost volume은 $W \times H \times D$ 구조다. Deep stereo에서도 의미는 같다. 다만 픽셀 intensity가 아니라 feature vector correlation을 쓰고, network가 cost volume을 정제한다.

- 높은 해상도의 cost volume: texture가 많은 미세 영역 탐색에 유리.
- 낮은 해상도의 cost volume: textureless region이나 넓은 영역의 안정적 탐색에 유리.
- cost volume이 커질수록 표현력은 좋아지지만 메모리와 계산량이 증가한다.

#### RAFT-Stereo

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.63-74

RAFT-Stereo는 deep stereo의 대표 예시다. 이름 자체보다 구조와 추정 방식이 중요하다.

| 단계 | RAFT-Stereo에서의 의미 | 시험 포인트 |
| --- | --- | --- |
| feature/context encoder | 좌우 영상의 feature map과 update에 쓸 context를 만든다 | raw pixel matching이 아니라 feature matching |
| correlation pyramid | 같은 행의 좌우 feature vector 내적을 모아 multi-level cost volume을 만든다 | $W/4 \times H/4 \times W/4$ 형태와 pyramid |
| iterative update | GRU가 현재 disparity를 보고 변화량 $\Delta d$를 반복 예측한다 | 단발성 argmin이 아니라 반복 보정 |
| disparity output | 기존 disparity에 $\Delta d$를 계속 더해 최종 disparity를 만든다 | stage가 진행될수록 예측이 정교해지는 구조 |

correlation pyramid는 마지막 차원에 대해 여러 pooling 크기를 적용해 4개 수준의 cost volume을 만든다. 큰 해상도는 세밀한 위치를 보고, 작은 해상도는 넓은 문맥과 textureless 영역을 본다.

#### deep stereo 장단점

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.75-83

| 장점 | 설명 |
| --- | --- |
| 어려운 영역 정확도 | textureless region, repetitive pattern에서 classical local method보다 강할 수 있다 |
| 조명 변화 대응 | feature와 학습 기반 정제가 단순 intensity cost보다 강인할 수 있다 |
| end-to-end 학습 | feature, cost, refinement를 한 pipeline에서 학습 가능 |

| 단점 | 설명 |
| --- | --- |
| generalization 문제 | 학습 데이터와 다른 환경에서는 성능이 떨어질 수 있다 |
| 학습 데이터 필요 | ground truth disparity나 대규모 stereo 데이터가 필요하다 |
| 계산 자원 | GPU, VRAM, 추론 시간이 중요한 제한이 된다 |

### 6. Learning objective: L1, L2, Huber, sequential loss

source anchor: `pdf/Computer_Vision_5_Stereo_Vision_v1.5.pdf` p.82-83

#### 개념 설명

Deep stereo는 예측 disparity $d_{pred}$와 정답 disparity $d_{gt}$의 차이를 loss로 줄인다. 여기서 중요한 것은 손실 함수의 이름 암기가 아니라, 오차 크기에 따라 penalty가 어떻게 달라지는지다.

#### formula / parameters

$$
L1=\frac{1}{N}\sum_p |d_{pred}(p)-d_{gt}(p)|
$$

$$
L2=\frac{1}{N}\sum_p \left(d_{pred}(p)-d_{gt}(p)\right)^2
$$

Huber loss, 또는 Smooth L1은 작은 오차에서는 L2처럼 부드럽게, 큰 오차에서는 L1처럼 덜 폭발적으로 동작한다.

$$
Huber(x)=
\begin{cases}
\frac{1}{2}x^2, & |x|<\delta \\
\delta\left(|x|-\frac{1}{2}\delta\right), & |x|\ge \delta
\end{cases}
$$

RAFT-Stereo의 sequential loss는 stage별 예측 $d_t$에 대한 L1 loss를 누적하고, 나중 stage에 더 높은 가중치를 둔다. 강의자료의 예시는 $\gamma=0.9$다.

$$
L_{seq}=\sum_{t=1}^{T}\gamma^{T-t}\left\|d_t-d_{gt}\right\|_1
$$

#### comparisons

| loss | 작은 오차 | 큰 오차 | 기억 포인트 |
| --- | --- | --- | --- |
| L1 | 선형 penalty | 선형 penalty | outlier에 L2보다 덜 민감 |
| L2 | 제곱 penalty | 매우 큰 penalty | 큰 오차를 강하게 벌한다 |
| Huber | L2처럼 매끄러움 | L1처럼 완만함 | L1과 L2의 절충 |
| sequential loss | stage별 L1 누적 | 나중 stage 비중 큼 | RAFT-Stereo의 iterative update 학습과 연결 |

#### likely exam questions

- 5지선다형: L1, L2, Huber의 outlier 민감도를 비교하는 형태.
- 4지선다형: sequential loss가 stage별 예측을 어떻게 다루는지 고르는 형태.
- 5지선다형: Huber가 작은 오차와 큰 오차에서 각각 어떤 loss처럼 동작하는지 묻는 형태.

### 1. 카메라 모델: 3D 점이 2D 픽셀로 보이는 과정

source:: `pdf/Computer_Vision_6_3D_Geometry_and_Camera_Parameters_v1.1.pdf` p.2-3

#### 개념 설명

핀홀 카메라 모델은 3D 공간의 점 $X=(X,Y,Z)$가 카메라 중심을 지나 영상 평면의 점 $x=(x,y)$에 맺힌다고 본다. 카메라 중심에서 영상 평면에 수직으로 내린 축이 principal axis이고, 이 축이 영상 평면과 만나는 점이 principal point $p=(p_x,p_y)$이다.

영상 좌표는 순수한 길이 단위가 아니라 pixel coordinate이다. 그래서 같은 물리적 카메라라도 센서 해상도, 픽셀 크기, 주점 위치가 달라지면 영상 좌표값이 달라진다.

#### 공식과 파라미터

기본 투영식은 다음처럼 깊이 $Z$로 나누는 형태다.

$$
x = \frac{fX}{Z}+p_x,\quad y = \frac{fY}{Z}+p_y
$$

- $f$: 초점거리. 강의에서는 pixel 단위로 다룬다.
- $p_x,p_y$: principal point의 pixel coordinate.
- $Z$: 카메라 좌표계에서의 깊이. 분모에 있으므로 영상 크기와 반비례 관계를 만든다.

#### 비례 관계와 비교

| 항목 | 관계 | 시험 함정 |
| --- | --- | --- |
| $X,Y$ | 커질수록 영상의 $x,y$가 커진다 | 물체가 옆으로 이동한 효과 |
| $Z$ | 커질수록 $\frac{X}{Z},\frac{Y}{Z}$가 작아진다 | 멀수록 작게 보임 |
| $f$ | 커질수록 영상에서 더 크게 보인다 | 초점거리는 pixel 단위 내부 파라미터 |
| $p_x,p_y$ | 전체 영상 좌표 원점을 이동시킨다 | 보통 영상 중앙 근처지만 항상 정확한 중앙은 아님 |

#### 예상문항 포인트

- principal axis와 principal point의 정의를 구분할 수 있는가?
- $x=\frac{fX}{Z}+p_x$에서 $Z$가 커지면 영상 좌표 변화가 어떻게 되는가?
- pixel coordinate에서 초점거리 $f$와 주점 $p$가 왜 카메라 내부 특성인지 설명할 수 있는가?

### 2. homogeneous coordinates: 나눗셈 투영을 행렬곱으로 바꾸는 표현

source:: `pdf/Computer_Vision_6_3D_Geometry_and_Camera_Parameters_v1.1.pdf` p.9-13

#### 개념 설명

Euclidean coordinates는 2D 점을 $(x,y)$, 3D 점을 $(x,y,z)$처럼 표현한다. homogeneous coordinates는 좌표 뒤에 scale 성분을 하나 더 붙여 2D는 $(x,y,1)$, 3D는 $(x,y,z,1)$로 표현한다.

핵심은 같은 점을 여러 배수 표현으로 나타낼 수 있다는 점이다. 예를 들어 2D homogeneous 표현에서 $(wx,wy,w)$는 $(x,y,1)$과 같은 Euclidean 점을 뜻한다. 마지막 성분 $w$로 나누면 Euclidean representation으로 돌아간다.

#### 공식과 파라미터

$$
(wx,wy,w) \sim (x,y,1) \rightarrow (x,y)
$$

$$
(wx,wy,wz,w) \sim (x,y,z,1) \rightarrow (x,y,z)
$$

3D 좌표 변환도 homogeneous form에서는 회전과 translation을 하나의 행렬곱으로 쓸 수 있다.

$$
\begin{bmatrix}
x_c\\y_c\\z_c\\1
\end{bmatrix}
=
\begin{bmatrix}
R & t\\
0 & 1
\end{bmatrix}
\begin{bmatrix}
x\\y\\z\\1
\end{bmatrix}
$$

#### 왜 projection becomes matrix multiplication인가

Euclidean representation에서는 투영이 $Z$로 나누는 비선형 형태로 보인다. homogeneous representation에서는 먼저 행렬곱으로 $KX_c$ 또는 $PX_w$를 만들고, 마지막에 scale 성분으로 나누어 Euclidean pixel coordinate를 얻는다. 즉, 나눗셈은 마지막 정규화 단계로 미루고, 월드 좌표계 변환과 영상 투영을 하나의 matrix multiplication chain으로 합성한다.

#### 비례 관계와 비교

| 표현 | 좌표 예 | 장점 | 주의점 |
| --- | --- | --- | --- |
| Euclidean | $(x,y,z)$ | 실제 공간 좌표로 직관적 | translation과 projection 합성이 불편함 |
| homogeneous | $(x,y,z,1)$ 또는 $(wx,wy,wz,w)$ | 회전, translation, projection을 행렬곱으로 연결 | 마지막에 $w$ 또는 깊이 성분으로 나누어야 함 |

#### 예상문항 포인트

- $(9,15,3)$이 $(3,5,1)$과 같은 homogeneous 2D 점을 뜻하는 이유는 무엇인가?
- Euclidean 좌표와 homogeneous 좌표의 차이를 설명할 수 있는가?
- 좌표 변환을 여러 번 할 때 homogeneous coordinates가 유리한 이유를 행렬곱 관점에서 말할 수 있는가?

### 3. intrinsic parameter matrix K: 카메라 내부 특성

source:: `pdf/Computer_Vision_6_3D_Geometry_and_Camera_Parameters_v1.1.pdf` p.4-6

#### 개념 설명

intrinsic parameter는 카메라 자체와 영상 평면의 내부 설정을 나타낸다. 같은 3D 점을 보더라도 초점거리, 픽셀 축 비율, 축 기울어짐, principal point가 다르면 pixel coordinate가 달라진다.

#### 공식과 파라미터

일반적인 intrinsic matrix K는 다음과 같다.

$$
K=
\begin{bmatrix}
f_x & s & p_x\\
0 & f_y & p_y\\
0 & 0 & 1
\end{bmatrix}
$$

- $f_x,f_y$: x축과 y축 방향 focal length. 픽셀 크기가 축마다 다르면 서로 다를 수 있다.
- $s$: skew. 영상 좌표축이 완전히 직교하지 않을 때의 기울어짐 성분이다. 대부분의 일반 카메라에서는 0으로 둔다.
- $p_x,p_y$: principal point의 pixel coordinate.
- 마지막 행 $[0,0,1]$: homogeneous image coordinate를 유지하기 위한 구조다.

강의의 단순한 경우에는 $s=0$, $f_x=f_y=f$로 두어 다음처럼 쓴다.

$$
K=
\begin{bmatrix}
f & 0 & p_x\\
0 & f & p_y\\
0 & 0 & 1
\end{bmatrix}
$$

#### 비례 관계와 비교

| 파라미터 | 의미 | 값이 커질 때의 효과 |
| --- | --- | --- |
| $f_x$ | x축 focal length | 같은 $X/Z$가 더 큰 $x$ 변화로 나타남 |
| $f_y$ | y축 focal length | 같은 $Y/Z$가 더 큰 $y$ 변화로 나타남 |
| $s$ | skew | x좌표가 y축 성분의 영향을 받음 |
| $p_x,p_y$ | principal point | 영상 좌표의 기준점이 이동함 |

#### 예상문항 포인트

- intrinsic과 extrinsic 중 $f_x,f_y,s,p_x,p_y$가 어느 쪽인지 고르는 문제가 나올 수 있다.
- skew가 0이라는 말은 어떤 축 관계를 가정하는가?
- $f_x$와 $f_y$가 같은 경우와 다른 경우의 의미를 설명할 수 있는가?

### 4. extrinsic parameters [R|t]: 월드 좌표계를 카메라 좌표계로 옮기기

source:: `pdf/Computer_Vision_6_3D_Geometry_and_Camera_Parameters_v1.1.pdf` p.7-8

#### 개념 설명

extrinsic parameter는 카메라가 월드 좌표계 안에서 어디에 있고 어느 방향을 보는지를 나타낸다. 이 위치와 방향을 합쳐 camera pose라고 한다. 강의에서는 rotation matrix $R$과 translation vector $t$가 카메라 포즈를 결정한다고 설명한다.

#### 공식과 파라미터

world-to-camera relation은 다음과 같다.

$$
X_c = R X_w + t
$$

- $X_w$: world coordinate의 3D 점.
- $X_c$: camera coordinate의 3D 점.
- $R$: rotation matrix. 월드 좌표축을 카메라 좌표축 방향으로 회전시킨다.
- $t$: translation vector. 카메라 원점을 기준으로 좌표를 이동시킨다.

카메라 중심을 $C$라고 쓰면, 먼저 $X_w-C$로 카메라 중심 기준 좌표를 만들고 회전하므로 다음처럼 해석할 수 있다.

$$
X_c = R(X_w-C)=RX_w-RC
$$

따라서 강의의 $X_c=RX_w+t$에서 $t=-RC$로 볼 수 있다.

#### 비례 관계와 비교

| 구분 | intrinsic | extrinsic |
| --- | --- | --- |
| 무엇을 설명하는가 | 카메라 내부와 영상 평면 | 월드 안의 카메라 위치와 방향 |
| 대표 파라미터 | $f_x,f_y,s,p_x,p_y$ | $R,t$ |
| 좌표계 역할 | 카메라 좌표를 pixel coordinate로 바꿈 | world coordinate를 camera coordinate로 바꿈 |
| 시험 함정 | focal length를 외부 파라미터로 착각 | translation을 단순한 영상 평면 이동으로 착각 |

#### 예상문항 포인트

- camera pose가 무엇인지, 그리고 $R,t$가 각각 무엇을 결정하는지 설명할 수 있는가?
- $X_c = R X_w + t$가 world-to-camera 변환이라는 점을 고를 수 있는가?
- $t$가 카메라 중심 $C$ 자체와 항상 같은 벡터가 아니라는 점을 이해하는가?

### 5. camera matrix P = K[R|t]: 전체 투영 체인

source:: `pdf/Computer_Vision_6_3D_Geometry_and_Camera_Parameters_v1.1.pdf` p.14-15

#### 개념 설명

카메라 영상 좌표는 두 단계를 거친다. 먼저 extrinsic parameters $[R|t]$가 월드 좌표 $X_w$를 카메라 좌표 $X_c$로 바꾼다. 그다음 intrinsic matrix $K$가 카메라 좌표를 영상의 homogeneous pixel coordinate로 투영한다.

#### 공식과 파라미터

전체 camera matrix는 다음처럼 쓴다.

$$
P = K[R|t]
$$

$$
\tilde{x} \sim P\tilde{X}_w = K[R|t]\tilde{X}_w
$$

- $P$: camera matrix. 일반적으로 $3 \times 4$ 형태다.
- $K$: $3 \times 3$ intrinsic matrix.
- $[R|t]$: $3 \times 4$ extrinsic block.
- $\tilde{X}_w$: homogeneous world point.
- $\tilde{x}$: homogeneous image point.

마지막에는 $\tilde{x}=(u,v,w)$를 $(u/w,v/w)$로 나누어 실제 pixel coordinate를 얻는다.

#### proportional relationships와 ambiguity

homogeneous projection에서 $\tilde{x}$와 $\lambda\tilde{x}$는 같은 Euclidean image point를 나타낸다. 그래서 투영식은 등호보다 proportional 관계, 즉 $\sim$로 쓰는 경우가 많다. 3D 점을 2D 영상으로 보낼 때 깊이 방향 정보가 압축되므로 scale/depth ambiguity가 생긴다. 같은 광선 위의 점들은 깊이가 달라도 영상에서는 같은 위치로 보일 수 있다.

| 관계 | 의미 | 시험 함정 |
| --- | --- | --- |
| $\tilde{x} \sim P\tilde{X}$ | scale이 달라도 같은 영상 점 | homogeneous 좌표의 배수 표현 |
| $Z$ 증가 | 영상 크기 감소 | 원근 투영의 깊이 효과 |
| 3D에서 2D 투영 | 깊이 정보 손실 | 한 장의 영상만으로 절대 깊이 확정 불가 |

#### 예상문항 포인트

- P = K[R|t]에서 $K$, $R$, $t$의 역할을 순서대로 설명할 수 있는가?
- 왜 $\tilde{x}=P\tilde{X}$가 아니라 $\tilde{x}\sim P\tilde{X}$로 쓰는가?
- camera matrix $P$의 크기와 입력/출력 좌표의 차원을 고를 수 있는가?

### 6. calibration: 실제 카메라 파라미터 추정

source:: `pdf/Computer_Vision_6_3D_Geometry_and_Camera_Parameters_v1.1.pdf` p.16-17

#### 개념 설명

calibration은 실제 카메라의 내부 파라미터와 외부 파라미터를 추정하는 작업이다. 강의에서는 여러 카메라가 월드 좌표계 안에 있을 때 각 카메라의 $K_i[R_i|t_i]$를 구하는 문제로 제시한다.

#### 추정 대상

| 대상 | 추정 파라미터 | 의미 |
| --- | --- | --- |
| internal parameters | $K$, $f_x,f_y,s,p_x,p_y$ | 영상 평면과 픽셀 좌표의 내부 특성 |
| external parameters | $R,t$ | 실제 3D 공간에서 카메라의 위치와 방향 |
| camera matrix | $P=K[R|t]$ | 월드 점을 영상 점으로 보내는 전체 투영 모델 |

calibration의 목적은 3D 공간에서 실제 카메라가 어디에 있고, 어느 방향을 향하며, 영상 평면 어디에 상이 맺히는지를 모델링하는 것이다. 스테레오 영상 보정(rectification)처럼 두 영상 사이의 기하관계를 알아야 하는 작업의 전제도 된다.

#### 비교와 함정

- calibration은 단순히 초점거리 하나만 구하는 작업이 아니다.
- 여러 카메라가 있으면 각 카메라마다 $K_i$, $R_i$, $t_i$가 다를 수 있다.
- 알려진 패턴이나 대응점으로 파라미터를 추정하지만, 시험에서는 구현 절차보다 무엇을 추정하는지와 왜 필요한지가 핵심이다.

#### 예상문항 포인트

- camera calibration의 목적을 한 문장으로 설명할 수 있는가?
- calibration에서 intrinsic과 extrinsic 중 무엇을 추정하는지 고를 수 있는가?
- stereo rectification과 calibration이 연결되는 이유를 기하관계 관점에서 설명할 수 있는가?

### 7. rotation matrix, orthogonal matrix, DoF

source:: `pdf/Computer_Vision_6_3D_Geometry_and_Camera_Parameters_v1.1.pdf` p.23-24

#### 개념 설명

rotation matrix는 좌표축의 방향을 바꾸는 행렬이다. 회전은 길이와 각도를 보존해야 하므로 rotation matrix는 orthogonal matrix의 성질을 가진다. Orthogonal matrix는 열벡터 또는 행벡터가 서로 정규직교인 행렬이며, 역행렬이 전치행렬과 같다.

#### 공식과 성질

2D rotation matrix는 한 각도 $\theta$로 결정된다.

$$
R_{2D}=
\begin{bmatrix}
\cos\theta & -\sin\theta\\
\sin\theta & \cos\theta
\end{bmatrix}
$$

rotation matrix의 핵심 성질은 다음과 같다.

- $R^{-1}=R^T$
- $R^TR=RR^T=I$
- $\det(R)=1$
- 길이와 각도를 보존한다.
- orthogonal matrix끼리의 곱도 orthogonal matrix이다.

#### DoF

DoF는 시스템 상태를 결정하기 위해 필요한 독립 변수의 수다.

| 대상 | DoF | 설명 |
| --- | --- | --- |
| 2D rotation | 1 DoF | 각도 $\theta$ 하나로 결정 |
| 3D rotation | 3 DoF | 3차원 회전 상태는 독립 회전 변수 3개로 결정 |
| translation in 3D | 3 DoF | x, y, z 방향 이동량 |
| camera pose in 3D | 6 DoF | rotation 3 DoF + translation 3 DoF |

#### 예상문항 포인트

- rotation matrix가 orthogonal matrix인 이유와 $R^{-1}=R^T$ 성질을 연결할 수 있는가?
- 2D rotation의 DoF와 3D rotation의 DoF를 구분할 수 있는가?
- camera pose를 6 DoF로 말하는 이유를 rotation과 translation으로 분해할 수 있는가?

확정 기말 범위: [[pdf/Computer_Vision_LMS.pdf|Computer_Vision_LMS.pdf]]

### 1. 범위와 출제 감각

- 이 LMS 자료는 기말 범위의 최종 보강 자료로, 최근 깊이 추정 foundation model과 neural rendering 흐름을 묶는다. source: [[pdf/Computer_Vision_LMS.pdf#page=1|Computer_Vision_LMS.pdf p.1]]

### 2. Depth Anything

source: [[pdf/Computer_Vision_LMS.pdf#page=2|Computer_Vision_LMS.pdf p.2]], [[pdf/Computer_Vision_LMS.pdf#page=3|p.3]], [[pdf/Computer_Vision_LMS.pdf#page=4|p.4]]

- Depth Anything은 단안 깊이 추정(Monocular Depth Estimation)의 대표적인 foundation model이다.
- 입력: 한 장 또는 여러 장의 RGB 영상.
- 출력: depth map. 최신 설명에서는 metric scale과 픽셀별 광선 예측까지 연결된다.
- 학습: semi-supervised learning과 knowledge distillation, 즉 student-teacher model 기반 학습이 핵심이다.
- 구조: DINOv2를 encoder로 사용하고 DPT(Dense Prediction Transformer)를 decoder로 사용한다.
- v1: metric scale 지원.
- v2: DA3-Giant, DA3-Large, DA3-Base, DA3-Small처럼 여러 모델 크기를 지원.
- v3: Dual-DPT head로 depth map과 픽셀별 ray를 동시에 예측한다.
- 장점: 단안 영상에서도 강한 depth prior를 제공하고, 여러 downstream 3D 복원 기술의 초기 기하 정보로 쓰기 좋다.
- 단점/주의: 실제 장면별 카메라 조건, 스케일, 기하 일관성 문제는 별도 방법과 결합해 보완해야 한다.
- 왜 필요: stereo pair나 정확한 3D 스캔 없이도 영상에서 깊이와 3D 구조를 추정하기 위한 기반 모델이 필요하기 때문이다.

> [!question] 객관식 예상 형태
> - 4지선다: Depth Anything 설명 중 틀린 것 고르기. 예: 카메라 파라미터를 반드시 알아야 한다는 선택지는 함정.
> - 5지선다: encoder/decoder 조합, semi-supervised, knowledge distillation, metric scale, Dual-DPT head를 섞어 옳은 설명 고르기.

### 3. ViT와 DINO

source: [[pdf/Computer_Vision_LMS.pdf#page=5|Computer_Vision_LMS.pdf p.5]], [[pdf/Computer_Vision_LMS.pdf#page=6|p.6]], [[pdf/Computer_Vision_LMS.pdf#page=7|p.7]]

- ViT(Vision Transformer)는 자연어 처리의 Transformer 구조를 영상 처리에 적용한 모델이다.
- ViT 입력: 영상을 정사각형 patch로 나눈 뒤, 각 patch를 1D vector로 펼치고 positional vector를 더한 token들.
- ViT 출력: self-attention을 통해 patch 사이 관계를 반영한 visual feature representation.
- ViT 핵심: convolution의 local filter보다, patch token 사이의 전역적인 self-attention 관계를 활용한다.
- DINO(Distillation with No Labels)는 label 없이 학습하는 self-supervised ViT 학습 알고리즘이자 이를 통해 얻은 ViT encoder이다.
- DINO 입력: 같은 이미지의 서로 다른 crop, 즉 global view와 local view.
- DINO 학습 목표: teacher model과 student model이 서로 다른 crop을 보고도 같은 표현을 만들도록 한다.
- DINO 결과: label 없이도 object boundary, edge, 객체 영역 단서와 비슷한 구조가 attention head에서 자연스럽게 나타난다.
- 장점: label 비용 없이 강한 visual backbone을 만들 수 있고, depth estimation과 여러 computer vision task의 encoder로 재사용된다.
- 단점/주의: DINO 자체가 depth map이나 3D 장면을 직접 출력하는 방법은 아니며, backbone 또는 representation 학습의 성격이 강하다.

> [!question] 객관식 예상 형태
> - 4지선다: ViT의 입력 처리 순서 고르기. patch 분할, 1D vector화, positional vector 추가, transformer encoder 입력.
> - 5지선다: DINO에 대한 설명 중 옳지 않은 것 고르기. label 기반 supervised 객체 영역 학습이라는 설명은 함정.

### 4. NeRF: implicit neural rendering

source: [[pdf/Computer_Vision_LMS.pdf#page=8|Computer_Vision_LMS.pdf p.8]], [[pdf/Computer_Vision_LMS.pdf#page=9|p.9]], [[pdf/Computer_Vision_LMS.pdf#page=10|p.10]]

- NeRF(Neural Radiance Fields)는 3D scene을 implicit하게 표현하는 MLP 기반 neural rendering 방법이다.
- implicit 의미: mesh나 point cloud처럼 물체를 직접 나열하지 않고, neural network의 연속 함수 안에 장면을 저장한다.
- 입력: 3D 위치 (x, y, z)와 viewing direction (theta, phi). 즉 5D function이다.
- 출력: radiance/color와 density.
- 렌더링: camera ray를 따라 여러 sample point를 뽑고, 각 sample의 color와 density를 예측한 뒤 volume rendering으로 pixel color를 계산한다.
- volume rendering 의미: ray를 따라 3D 공간의 density와 color를 누적/적분해 최종 2D image의 pixel color를 만드는 방식이다.
- 학습: 실제 영상과 생성 영상의 차이를 줄이도록 MLP parameter를 최적화한다.
- 장점: 투명 유리, 반사 금속, 털, 연기, 미세한 빛처럼 mesh/point cloud로 표현하기 어려운 appearance를 잘 표현할 수 있다.
- 장점: 고정된 topology 제약이 약해 복잡한 장면 표현에 유리하다.
- 단점: 장면 하나마다 학습 시간이 필요하다.
- 단점: pixel 하나를 만들 때도 ray 위의 많은 point를 network에 통과시켜야 하므로 rendering이 느릴 수 있다.
- 단점: explicit object primitive가 아니라 편집과 재사용이 어렵다.
- 왜 필요: 기존 3D 표현이 놓치기 쉬운 복잡한 appearance와 novel view synthesis를 neural network로 표현하기 위해 필요하다.

> [!question] 객관식 예상 형태
> - 4지선다: NeRF의 입력/출력(inputs/outputs) 조합 고르기. 입력은 position+direction, 출력은 radiance+density.
> - 5지선다: volume rendering 설명 중 틀린 것 고르기. 한 점의 색만 바로 복사한다는 설명은 함정.

### 5. 3D Gaussian Splatting: explicit neural rendering

source: [[pdf/Computer_Vision_LMS.pdf#page=11|Computer_Vision_LMS.pdf p.11]], [[pdf/Computer_Vision_LMS.pdf#page=12|p.12]], [[pdf/Computer_Vision_LMS.pdf#page=13|p.13]]

- 3D Gaussian Splatting(3DGS)은 3D Gaussian들을 primitive로 사용해 장면을 explicit하게 표현한다.
- 3D Gaussian 의미: 장면을 구성하는 개별 Gaussian primitive이며, 보통 위치, 회전, 크기, 색상, 불투명도(opacity)를 가진다.
- explicit 의미: 장면을 구성하는 요소와 parameter가 비교적 직접적인 primitive 집합으로 존재한다.
- 입력: camera view와 3D Gaussian parameter 집합.
- 출력: target view의 2D rendered image.
- 렌더링: target image의 tile별로 3D Gaussian들을 깊이에 따라 정렬하고 병렬 처리해 빠르게 rendering한다.
- Differentiable Pipeline: rendering 결과와 실제 image의 차이를 통해 Gaussian parameter를 조정할 수 있게 설계된다.
- 장점: NeRF보다 rendering이 빠르고, primitive 기반이라 장면 요소를 상대적으로 다루기 쉽다.
- 장점: explicit primitive를 사용하므로 실시간/고속 novel view rendering에 강하다.
- 단점: Gaussian parameter 최적화가 필요하고, 장면별 최적화 문제는 여전히 남을 수 있다.
- 단점/주의: 3DGS가 항상 semantic object 단위 편집을 자동으로 제공하는 것은 아니다.
- 왜 필요: NeRF의 느린 rendering과 per-pixel network query 부담을 줄이면서 고품질 view synthesis를 하기 위해 필요하다.

> [!question] 객관식 예상 형태
> - 4지선다: 3D 장면의 explicit 표현법이 아닌 것 고르기. network parameter는 NeRF 쪽 implicit 표현으로 연결되는 함정.
> - 5지선다: 3D Gaussian parameter에 해당하는 것 고르기. 위치, 회전, 크기, 색상, opacity가 핵심.

### 6. 4DGS

source: [[pdf/Computer_Vision_LMS.pdf#page=13|Computer_Vision_LMS.pdf p.13]]

- 4DGS(4D Gaussian Splatting)는 3D Gaussian Splatting을 동적 영상으로 확장한 기술이다.
- 3DGS가 정적 장면 표현에 강하다면, 4DGS는 시간 변화에 따른 Gaussian들의 변화를 정확하고 효율적으로 표현하는 것을 목표로 한다.
- 입력: 시간 t가 포함된 장면 상태 또는 시간에 따른 Gaussian deformation 정보.
- 출력: 특정 시간과 시점에서의 rendered image.
- 핵심: Gaussian parameter의 시간 변화에 따른 deformation 값을 추정하고, 이를 시간에 따라 update하거나 t를 입력으로 하는 함수 값으로 표현한다.
- 왜 필요: 사람, 물체, 카메라, 장면이 움직이는 dynamic scene에서는 정적 3DGS만으로는 시간 변화까지 표현하기 어렵기 때문이다.

> [!question] 객관식 예상 형태
> - 4지선다: 4DGS가 해결하려는 문제 고르기. 정적 3DGS를 시간 변화가 있는 dynamic scene으로 확장하는 것이 핵심.
> - 5지선다: 4DGS 설명 중 틀린 것 고르기. 시간 t나 deformation과 무관하다는 선택지는 함정.

### 7. Generalizable Neural Rendering

source: [[pdf/Computer_Vision_LMS.pdf#page=14|Computer_Vision_LMS.pdf p.14]], [[pdf/Computer_Vision_LMS.pdf#page=15|p.15]], [[pdf/Computer_Vision_LMS.pdf#page=16|p.16]], [[pdf/Computer_Vision_LMS.pdf#page=17|p.17]], [[pdf/Computer_Vision_LMS.pdf#page=18|p.18]]

- Neural Rendering은 computer graphics와 AI가 결합된 기술로, neural network를 활용해 3D 공간이나 물체를 표현하고 이를 2D image로 rendering한다.
- 대표 기술: NeRF, 3D Gaussian Splatting.
- 기존 약점: 장면별로 network 또는 3D Gaussian parameter를 optimization/training해야 한다.
- Generalizable Neural Rendering은 이 per-scene optimization 문제를 줄이기 위한 방향이다.
- 핵심: 대규모 데이터로 사전 학습된 하나의 feed-forward network를 사용한다.
- 목표: 별도 추가 학습 없이 실시간 또는 고속으로 3D 공간 정보를 즉시 추론하고 novel view를 합성한다.
- 입력: source image, camera/view 정보, depth prior 또는 feature처럼 장면을 추론할 단서.
- 출력: Gaussian parameter, depth 정보, target view rendered image 등 방법별로 필요한 3D/2D 결과.
- 장점: 새 장면마다 오래 최적화하지 않아도 되어 빠르다.
- 장점: foundation model이나 대규모 사전학습의 일반화 능력을 활용한다.
- 단점/주의: 사전학습 데이터 분포와 다른 장면에서는 품질이 떨어질 수 있고, 장면별 최적화만큼 세밀하지 않을 수 있다.
- 왜 필요: NeRF와 3DGS의 큰 병목인 per-scene optimization을 줄여 실제 응용에서 빠르게 3D 추론과 rendering을 하기 위해 필요하다.

#### GPS-Gaussian

source: [[pdf/Computer_Vision_LMS.pdf#page=16|Computer_Vision_LMS.pdf p.16]]

- GPS-Gaussian은 CVPR 2024의 Generalizable Neural Rendering 예시이다.
- 학습 데이터로 depth 정보 추정 network와 3D Gaussian parameter 추정 network를 사전 학습한다.
- 추론 시에는 사전 학습된 network를 통해 feed-forward 방식으로 Gaussian parameter 추정과 image synthesis를 수행한다.
- 입력: source image와 사전학습 network가 처리할 기하/시점 단서.
- 출력: 3D Gaussian parameter와 합성된 target image.

#### MonoSplat

source: [[pdf/Computer_Vision_LMS.pdf#page=17|Computer_Vision_LMS.pdf p.17]]

- MonoSplat은 CVPR 2025의 Generalizable Neural Rendering 예시이다.
- 단안 깊이 추정 foundation model의 강한 geometric visual prior를 활용한다.
- 단안 feature의 부족한 geometric consistency를 lightweight attention으로 보완한다.
- 입력: monocular image 기반 feature와 depth prior.
- 출력: 3D Gaussian Splatting 기반 장면 표현 또는 target view 합성 결과.

> [!question] 객관식 예상 형태
> - 4지선다: Generalizable Neural Rendering이 해결하려는 핵심 한계 고르기. per-scene optimization이 정답 후보.
> - 5지선다: GPS-Gaussian과 MonoSplat의 공통점 고르기. feed-forward 일반화와 3D Gaussian/깊이 prior 활용이 핵심.

### 8. implicit vs explicit 비교

source: [[pdf/Computer_Vision_LMS.pdf#page=8|Computer_Vision_LMS.pdf p.8]], [[pdf/Computer_Vision_LMS.pdf#page=11|p.11]], [[pdf/Computer_Vision_LMS.pdf#page=14|p.14]]

| 구분 | NeRF | 3D Gaussian Splatting |
| --- | --- | --- |
| representation | implicit MLP function | explicit 3D Gaussian primitives |
| 입력 | position, viewing direction | camera/view, Gaussian parameter |
| 출력 | radiance, density | rendered image, Gaussian contribution |
| rendering | volume rendering | splatting/tile-based parallel rendering |
| 장점 | 복잡한 appearance 표현, topology 제약 약함 | 빠른 rendering, explicit primitive 기반 |
| 단점 | 장면별 학습, 느린 rendering, 편집 어려움 | 장면별 parameter 최적화 가능성, semantic 편집은 별도 문제 |
| 시험 함정 | NeRF를 explicit mesh 방식이라고 하는 선택지 | 3D Gaussian을 implicit MLP라고 하는 선택지 |

### 9. 마지막 정리

- Depth Anything: 단안 depth foundation model. DINOv2 encoder와 DPT decoder, semi-supervised, knowledge distillation, metric scale이 키워드다.
- ViT: image patch token과 self-attention으로 visual feature를 만든다.
- DINO: label 없이 teacher-student와 multi-crop으로 ViT encoder를 학습한다.
- NeRF: implicit 5D function. 입력은 position/direction, 출력은 radiance/density, rendering은 volume rendering이다.
- 3D Gaussian Splatting: explicit primitive 방식. 위치, 회전, 크기, 색상, opacity를 가진 3D Gaussian으로 빠르게 rendering한다.
- 4DGS: 3DGS를 시간 변화가 있는 dynamic scene으로 확장한다.
- Generalizable Neural Rendering: per-scene optimization을 줄이기 위해 feed-forward 사전학습 network로 3D 정보와 rendering 결과를 빠르게 추론한다.
- GPS-Gaussian: depth 추정 network와 Gaussian parameter 추정 network를 사전학습해 feed-forward 합성을 수행한다.
- MonoSplat: monocular depth foundation model의 geometric prior와 lightweight attention을 활용한다.
