> [!abstract]
> 퍼셉트론은 입력 특성에 가중치를 적용해 하나의 점수를 만들고, 그 결과로 분류를 결정하는 가장 단순한 신경망 단위다. 벡터화는 같은 연산을 많은 데이터에 한꺼번에 적용해 계산 흐름을 단순화한다.

## 가중합으로 만드는 경계

입력 (x_1, x_2, ldots)에는 각각 가중치가 연결되고, 가중합은 한 점수로 모인다. 가중치를 조정하는 과정이 학습이며, 결과적으로 입력 공간에서 클래스를 나누는 직선이나 평면의 경계가 만들어질 수 있다.

<Tabs>
<Tab title="입력">
각 관측치를 설명하는 수치 특성이다.
</Tab>
<Tab title="가중치">
특성이 점수에 미치는 상대적 영향을 조정하는 학습 대상이다.
</Tab>
<Tab title="출력">
가중합을 기준과 비교해 분류 또는 다음 계산으로 전달한다.
</Tab>
</Tabs>

```mermaid
flowchart LR
    A[입력 특성] --> B[가중치 곱]
    B --> C[가중합]
    C --> D[기준과 비교]
    D --> E[분류 결과]
    E -.오차 정보.-> B
```

> [!important]
> 퍼셉트론의 가중치는 단순한 계수이면서 동시에 학습으로 바뀌는 파라미터다. 입력과 출력의 관계를 정하는 책임이 있으므로, 데이터 표현이 바뀌면 해석도 함께 달라진다.

<details>
<summary>가중치가 “학습된다”는 말은 무엇일까?</summary>

학습 절차는 예측과 목표의 차이를 기준으로 가중치를 조정한다. 한 번의 값이 정답인 것이 아니라, 훈련 데이터와 갱신 규칙이 어떤 경계를 만들었는지 검증으로 확인한다.
</details>

## 배열 연산으로 넓히기

배열 원소를 반복문으로 하나씩 처리할 수도 있지만, 같은 연산을 배열 전체에 적용하는 벡터화는 의도를 더 직접적으로 표현한다. 자료는 단일 명령을 여러 데이터에 적용하는 SIMD와 배열 기반 계산의 연결을 함께 다룬다.


<details>
<summary>벡터화가 항상 같은 성능을 보장할까?</summary>

벡터화는 많은 수치 연산을 효율적으로 실행할 기회를 주지만, 실제 성능은 배열 크기·메모리 배치·라이브러리 구현·하드웨어에 따라 달라진다. 측정 없이 성능을 단정하지 않는다.
</details>

> [!warning]
> 퍼셉트론의 직선 경계와 벡터화의 계산 효율을 혼동하지 않는다. 하나는 모형의 표현 방식이고, 다른 하나는 데이터를 처리하는 구현 방식이다.

**핵심 연결:** 가중치는 분류 경계를 만들고, 벡터화는 많은 입력에 그 계산을 적용하는 효율적인 표현을 제공한다.

> [!tip]
> 학습 팁: 핵심 개념을 작은 입력 예시로 다시 설명하고, 검증 기준을 한 문장으로 적어 본다.

### 스스로 점검

- 입력·가중치·출력의 역할을 구분하는가?
- 분류 경계가 가중치와 어떤 관계인지 설명할 수 있는가?
- 알고리즘의 표현력과 구현 성능을 분리해 평가하는가?
