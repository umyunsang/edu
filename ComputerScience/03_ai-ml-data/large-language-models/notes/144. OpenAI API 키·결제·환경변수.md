> [!NOTE]
> API 사용 준비는 패키지 설치, 계정·결제 설정, 키 발급, 비밀값 저장, 사용량 확인으로 나뉜다. 키를 만들었다는 사실과 키 값을 안전하게 다룬다는 것은 별도 검증 항목이다.

## 준비 흐름

```mermaid
flowchart LR
    A[패키지 설치] --> B[결제 설정]
    B --> C[한도 설정]
    C --> D[키 발급]
    D --> E[환경변수 로딩]
```

| 단계 | 원문 작업 | 완료 기준 |
| :-- | :-- | :-- |
| SDK | `pip install openai` | 프로젝트 환경에 패키지가 설치됨 |
| 계정 | 플랫폼 로그인 | 사용할 조직·프로젝트가 맞음 |
| 결제 | 결제 수단과 크레딧 설정 | 현재 청구 상태를 콘솔에서 확인 |
| 한도 | 월간 예산과 알림 임계값 설정 | 숫자와 알림 수신 경로 확인 |
| 키 | API 키 생성 | 비밀 저장소에 한 번만 안전하게 보관 |
| 환경 | 프로젝트 환경변수로 로딩 | 값 자체를 출력하지 않고 존재만 확인 |
| 사용량 | 사용량 화면 확인 | 요청량과 청구 내역 점검 |

<details>
<summary>설치 위치를 먼저 확인하는 이유</summary>

`pip`가 시스템 Python이 아니라 프로젝트의 Conda·가상환경 Python에 연결됐는지 확인해야 한다. 그렇지 않으면 설치 성공 메시지가 나와도 실행 환경에서 패키지를 찾지 못할 수 있다.

</details>

## 결제와 사용 한도

| 원문 화면 순서 | 제시된 작업 | 경계 |
| :-- | :-- | :-- |
| Billing | Payment methods에서 카드 등록 | 조직·개인 계정 구분 |
| 결제 세부정보 | Individual 선택과 영문 주소 입력 | 화면·요구 필드는 시점에 따라 변경 |
| 크레딧 | 사용할 만큼 잔액 추가 | 원문은 최소 USD 5라고 설명 |
| Limits | 월간 예산 입력 | 과금 차단인지 알림 기준인지 확인 |
| 알림 | 이메일 알림 임계값 입력 | 알림 수신 주소와 임계값 확인 |
| Usage | API 사용량 확인 | 실제 요청과 비용 추적 |

<Tabs>
  <Tab label="예산">원문은 월간 사용 한도를 지정하고 도달하면 API가 멈춘다고 설명한다.</Tab>
  <Tab label="알림">설정한 비용 임계값에 도달하면 이메일을 보낸다고 설명한다.</Tab>
  <Tab label="쿼터 오류">결제 수단이 없을 때 `insufficient_quota` 오류 예를 제시한다.</Tab>
</Tabs>

> [!WARNING]
> 원문 UI에는 “Set a monthly budge”라고 적혀 있는데 budget의 오탈자로 보인다. 또한 예산을 0으로 넣어 None으로 만들면 과금 요청이 거부된다는 설명은 표현과 동작이 충돌하므로 하드 캡으로 믿지 말고 현재 콘솔의 실제 의미를 확인해야 한다.

<details>
<summary>금액 정보의 시점성</summary>

최소 충전액 USD 5, 메뉴 이름, Individual 선택지, 예산 동작은 모두 원문 작성 시점의 화면 안내다. 현재 계정 유형과 지역, 청구 방식에 그대로 적용된다고 단정하지 않는다.

</details>

## 키 생명주기

| 단계 | 안전한 처리 | 피할 처리 |
| :-- | :-- | :-- |
| 생성 | 사용할 프로젝트·권한을 확인 | 용도를 구분하지 않은 공용 키 |
| 확인 | 생성 직후 한 번만 복사 | 화면에서 다시 볼 수 있다고 가정 |
| 저장 | 비밀 저장소 또는 로컬 환경 파일 | 메모·채팅·공개 문서에 붙여넣기 |
| 사용 | 환경변수에서 읽기 | 소스 코드에 직접 대입 |
| 검증 | 존재 여부와 요청 성공으로 확인 | 전체 키 문자열 출력 |
| 유출 대응 | 즉시 폐기하고 새 키 발급 | 같은 키를 계속 사용 |
| 점검 | 사용량과 청구 내역 검토 | 예상 밖 비용을 방치 |

> [!DANGER]
> 원문 마지막 예제는 환경변수의 API 키 전체를 콘솔에 출력한다. 이 노트는 해당 코드를 재현하지 않는다. 터미널 로그·노트북 출력·화면 공유에 비밀값이 남을 수 있으므로 값이 아니라 설정 여부만 확인한다.

키 값은 생성 순간부터 출력물이 아니라 자격 증명으로 취급한다.

> [!IMPORTANT]
> 원문은 생성한 키가 창을 닫은 뒤 다시 표시되지 않는다고 경고한다. 분실 시 복구하려 하지 말고 기존 키를 폐기한 뒤 새 키를 발급하는 흐름을 준비한다.

## 환경변수로 로딩

**핵심:** 원문은 프로젝트 루트의 `.env`에 키를 두고 `python-dotenv`의 `load_dotenv`로 불러오는 흐름을 제시한다.

```python
from dotenv import load_dotenv

load_dotenv()
```

| 점검 | 안전한 확인 |
| :-- | :-- |
| 파일 위치 | 실행 기준 디렉터리에서 `.env`를 찾는지 |
| 버전 관리 | `.env`가 추적 대상에서 제외됐는지 |
| 파일 권한 | 필요한 사용자만 읽을 수 있는지 |
| 변수 이름 | SDK가 기대하는 환경변수 이름과 일치하는지 |
| 로딩 성공 | 변수 존재 여부만 불리언으로 검사 |
| 프로세스 범위 | 새 셸·IDE·노트북 커널에 반영됐는지 |

```mermaid
flowchart LR
    A[비밀 저장] --> B[환경 로딩]
    B --> C[존재 확인]
    C --> D[API 요청]
    D --> E[사용량 점검]
```

<details>
<summary>값을 노출하지 않는 검증</summary>

환경변수 이름이 존재하는지, 비어 있지 않은지, 최소 권한의 시험 요청이 성공하는지를 확인한다. 키의 접두사·길이·전체 문자열을 출력하거나 예외 로그에 포함하지 않는다.

</details>

## 오류와 대응

| 원문 오류 정보 | 의미 | 먼저 확인할 것 |
| :-- | :-- | :-- |
| type `insufficient_quota` | 현재 쿼터를 초과했다고 보고 | 결제 상태, 잔액, 조직·프로젝트 |
| code `insufficient_quota` | 같은 원인의 코드 | 올바른 계정 자격 증명인지 |
| param `null` | 특정 요청 파라미터 문제가 아님 | 청구·쿼터 설정 |
| 요청 거부 | API 호출이 진행되지 않음 | 콘솔 사용량과 오류 발생 시각 |

> [!CAUTION]
> `insufficient_quota`를 단순한 코드 오류로 처리하지 않는다. 결제 수단 등록 여부만이 아니라 잔액, 조직 선택, 프로젝트 제한, 원문 이후 바뀐 청구 정책을 함께 확인한다.

## 원문 보안·재현성 경고

| 원문 관행 | 위험 | 이 노트의 경계 |
| :-- | :-- | :-- |
| 키를 “다른 곳”에 저장 | 저장 위치와 접근 통제 불명확 | 전용 비밀 저장소 또는 로컬 비추적 파일 |
| 키 전체 출력 | 로그·화면 공유로 유출 | 존재 여부만 검사 |
| 원격 requirements 파일 직접 설치 | 외부 내용이 바뀌는 공급망 위험 | 검토·고정한 의존성 사용 |
| 주소 변환 사이트 사용 | 개인정보를 제3자에 전달할 수 있음 | 결제 사업자가 요구하는 공식 입력 기준 확인 |
| 화면 메뉴 이름에 의존 | UI 변경 시 절차 중단 | 목적과 완료 기준 중심으로 검증 |

> [!WARNING]
> 원문은 외부 저장소의 requirements 파일을 URL에서 곧바로 설치하는 명령을 제시한다. 이 노트는 그 명령과 주소를 재현하지 않는다. 의존성 내용을 검토하고 버전을 고정한 뒤 신뢰할 수 있는 경로에서 설치해야 한다.

## 정리

- 패키지 설치, 결제, 한도, 키, 환경변수, 사용량은 각각 별도 완료 기준을 둔다.
- 월간 예산을 과금 중단 장치로 단정하지 않고 현재 콘솔 동작을 확인한다.
- 키는 소스·노트북·로그에 출력하지 않으며 유출 시 즉시 폐기한다.
- `.env`는 버전 관리에서 제외하고 최소 권한으로 보관한다.
- 원격 의존성 설치와 제3자 주소 도구는 보안·개인정보 경계를 먼저 검토한다.
