## Python 배포판 선택

| 항목 | Anaconda | Miniconda |
| :-- | :-- | :-- |
| 기본 구성 | 데이터 과학·머신러닝 라이브러리를 폭넓게 포함 | Conda와 최소 구성에서 시작 |
| 원문 설치 크기 | 약 3GB 이상 | 약 50–100MB |
| 장점 | 초기 설정이 단순하고 주요 패키지를 빠르게 사용 | 필요한 패키지만 골라 가벼운 환경 구성 |
| 단점 | 저장 공간과 불필요 패키지 부담 | 초기 패키지 선택·설치 시간이 필요 |
| 선택 기준 | 즉시 쓸 패키지가 많을 때 | 프로젝트별 최소 환경을 만들 때 |

<details>
<summary>크기 수치의 경계</summary>

설치 파일과 기본 패키지 크기는 배포판·운영체제·시점에 따라 달라진다. 표의 약 3GB 이상과 약 50–100MB는 원문 시점의 비교값이지 현재 설치 용량 보장이 아니다.

</details>

## Conda 환경 구성 흐름

```mermaid
flowchart LR
    A[채널 확인] --> B[우선순위 설정]
    B --> C[환경 생성]
    C --> D[환경 활성화]
    D --> E[패키지 설치]
```

| 단계 | 원문 명령의 의도 | 실행 전 확인 |
| :-- | :-- | :-- |
| 채널 확인 | `conda config --show channels` | 현재 채널 순서 |
| 채널 추가 | conda-forge를 추가 | 신뢰할 채널과 조직 정책 |
| 우선순위 | strict로 설정 | 기존 환경에 미치는 영향 |
| 환경 생성 | 이름과 Python 3.12 지정 | 프로젝트가 요구하는 Python 버전 |
| 목록 확인 | `conda info --envs` | 새 환경이 만들어졌는지 |
| 활성화 | 선택한 환경 이름 사용 | 프롬프트에 활성 환경 표시 |
| 패키지 설치 | notebook·시각화·데이터 패키지 설치 | 패키지 이름과 구분자 |

<Tabs>
  <Tab label="Conda 경로">프로젝트별 환경을 만들고 필요한 패키지를 Conda로 관리한다.</Tab>
  <Tab label="pyenv 경로">원문 후반의 별도 경로로 Python 3.11 설치와 전역 버전 설정이 제시된다.</Tab>
  <Tab label="혼용 전 확인">두 도구가 같은 셸에서 어떤 Python 실행 파일을 선택하는지 먼저 확인한다.</Tab>
</Tabs>

> [!WARNING]
> 원문 환경 생성 명령의 옵션은 ASCII 하이픈이 아닌 긴 대시 `–y`로 보이고, 패키지 설치 예에는 `notebook, seaborn, matplotlib`처럼 쉼표가 들어 있다. 그대로 복사하지 말고 CLI가 인식하는 옵션과 공백 구분 패키지 목록으로 다시 확인해야 한다.

두 Python 버전 경로도 하나로 합치지 않는다.

> [!CAUTION]
> Conda 예시는 Python 3.12를 지정하지만 뒤의 pyenv 예시는 3.11을 전역 버전으로 지정한다. 두 값은 서로 다른 설치 경로의 예이며 한 프로젝트의 동시 요구사항이 아니다.

## Git 설치와 확인

| 단계 | 원문 안내 | 검증할 결과 |
| :-- | :-- | :-- |
| 설치 프로그램 | 64비트 Git for Windows 설치본 선택 | 운영체제 아키텍처와 출처 |
| 설치 옵션 | 옵션을 확인하며 진행 | PATH, 기본 편집기, 줄바꿈 설정 |
| 셸 재시작 | 설치 뒤 새 PowerShell 열기 | 변경된 PATH 반영 |
| 동작 확인 | `git` 명령 입력 | 도움말 또는 버전 정보가 출력되는지 |

<details>
<summary>“전부 Next”를 그대로 따르지 않는 이유</summary>

원문은 나머지 설치 단계를 Next 버튼으로 진행하라고 하지만, 기본 편집기·PATH·줄바꿈 같은 선택은 이후 개발 환경에 영향을 준다. 화면의 실제 옵션을 확인하고 프로젝트 정책에 맞게 선택한다.

</details>

## PowerShell 정책과 관리자 권한

**핵심:** 원문은 PowerShell을 관리자 권한으로 열어 정책을 적용하고, 재시작한 뒤 pyenv 설치와 환경변수 추가를 진행하는 순서를 제시한다.

| 순서 | 확인 가능한 원문 내용 | 추출문에 없는 내용 |
| :-- | :-- | :-- |
| 1 | 관리자 권한 PowerShell 실행 | 적용할 정확한 정책 명령 |
| 2 | 정책 적용 후 PowerShell 재시작 | 정책 범위와 값 |
| 3 | 관리자 권한으로 pyenv 설치 | 설치 명령과 배포판 |
| 4 | 환경변수 추가 | 변수 이름·경로·적용 범위 |
| 5 | Python 3.11 설치·전역 지정 | 현재 셸에서의 실제 실행 파일 |

> [!DANGER]
> 원문은 관리자 권한 실행을 반복 권장하지만, 정확한 명령과 변경 범위가 추출문에 없다. 출처를 확인하지 않은 명령을 관리자 셸에서 실행하지 말고, 가능한 경우 사용자 범위와 최소 권한을 우선한다.

이미지 의존 구간은 빈칸을 사실로 채우지 않는다.

> [!IMPORTANT]
> 정책 명령과 환경변수 값은 슬라이드 이미지에만 있었던 것으로 보이며 현재 추출 텍스트에 남지 않았다. 이 노트는 값을 추정하거나 재구성하지 않는다.

## 환경변수 점검

| 점검 항목 | 확인 방법의 목적 |
| :-- | :-- |
| 변수 범위 | 사용자 변수인지 시스템 변수인지 구분 |
| PATH 순서 | Conda·pyenv·시스템 Python의 우선순위 확인 |
| 셸 재시작 | 새 프로세스에 변경이 반영됐는지 확인 |
| Python 선택 | `python`과 패키지 관리자가 같은 환경을 가리키는지 확인 |
| 중복 경로 | 오래된 Python·Git 경로가 앞에 남지 않았는지 확인 |

```text
설치 성공 ≠ PATH 선택 성공 ≠ 프로젝트 환경 활성화
```

## VS Code 구성

| 구성 | 원문 작업 | 확인점 |
| :-- | :-- | :-- |
| VS Code | Windows 설치본 설치 | 실행과 업데이트 가능 여부 |
| Python 확장 | 확장 검색에서 Python 설치 | 신뢰할 게시자와 활성화 상태 |
| Jupyter 확장 | 확장 검색에서 Jupyter 설치 | 노트북 파일 실행 지원 |
| 인터프리터 | 원문에 상세 절차 없음 | 프로젝트의 Conda 또는 pyenv Python 선택 |
| 노트북 커널 | 원문에 상세 절차 없음 | 선택한 환경과 커널 일치 |

<details>
<summary>마지막 검증 순서</summary>

새 터미널에서 Git을 확인하고, 선택한 Python 환경을 활성화한 뒤, VS Code의 인터프리터와 Jupyter 커널이 같은 환경을 가리키는지 확인한다.

</details>

> [!WARNING]
> 원문에는 “Window 키”라는 표기가 나오며 Windows 키의 오탈자로 보인다. 설치 크기, Python 버전, 확장 화면, PowerShell 정책도 특정 시점의 안내이므로 현재 화면과 다를 수 있다.

## 정리

- Anaconda와 Miniconda는 초기 패키지 범위와 설치 크기의 선택이다.
- Conda의 Python 3.12 예와 pyenv의 3.11 예는 별도 경로로 읽는다.
- 긴 대시와 쉼표가 섞인 원문 명령은 그대로 실행하지 않는다.
- 관리자 권한은 정확한 명령·범위·출처를 확인한 뒤 최소화한다.
- Git, Python 인터프리터, Jupyter 커널이 같은 프로젝트 환경을 바라보는지 끝에서 검증한다.
