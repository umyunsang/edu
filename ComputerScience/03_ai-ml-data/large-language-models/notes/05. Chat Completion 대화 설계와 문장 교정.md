**Chat Completion API**는 메시지의 리스트(`messages`)를 입력받아 AI가 이전 맥락을 기억하는 상태로 연속적인 상호작용을 수행하는 표준 대화형 인터페이스이다.

---

## 1. 메시지 3대 역할 (Message Roles)

| 역할 (`role`) | 주체 | 핵심 기능 및 지침 |
| :--- | :--- | :--- |
| `system` | 시스템 관리자 | AI의 행동 양식, 페르소나, 말투, 출력 포맷(JSON 등), 금기 사항 규정 |
| `user` | 인간 사용자 | 실제 질문, 요청 사항, 분석할 원문 텍스트 주입 |
| `assistant` | 인공지능 모델 | AI 모델의 이전 응답 기록 (다중 턴 문맥 유지용) |

---

## 2. 멀티 턴 대화의 컨텍스트 토큰 누적 수학적 모델링

LLM은 상태를 저장하지 않는(Stateless) API 구조이므로 이전 대화를 기억하게 하려면 과거의 모든 대화 히스토리를 매 요청마다 누적하여 재전송해야 한다.

총 $K$번의 대화 왕복 턴이 진행될 때, $k$번째 요청 시 모델로 입력되는 프롬프트 토큰 수 $T_k$와 전체 세션 누적 토큰 $T\_{\text{cum}}$은 다음과 같다:

$$T_k = |s| + \sum_{j=1}^k (|u_j| + |a_{j-1}|)$$

$$T_{\text{cum}} = \sum_{k=1}^K T_k = K \cdot |s| + \sum_{k=1}^K (K - k + 1)(|u_k| + |a_k|) = \mathcal{O}(K^2 \cdot \bar{L})$$

여기서 $|s|$는 시스템 프롬프트 길이, $|u_k|$는 사용자 입력 길이, $|a_k|$는 어시스턴트 응답 길이, $\bar{L}$은 턴당 평균 메시지 길이이다. 대화가 길어질수록 API 호출 비용과 컨텍스트 소모는 턴 수의 제곱($\mathcal{O}(K^2)$)으로 급증하므로, 장기 대화에서는 **요약 버퍼 메모리(Summary Buffer Memory)** 또는 **슬라이딩 윈도우(Sliding Window)** 전략이 필수적이다.

## 3. 다중 턴 대화 및 문장 교정 파이썬 실습 코드

```python
import os
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

# 1. 다중 턴(Multi-turn) 대화 컨텍스트 구성
messages = [
    {"role": "system", "content": "당신은 IT 전문 테크니컬 라이터입니다. 친절하고 간결하게 설명하세요."},
    {"role": "user", "content": "쿠버네티스(Kubernetes)의 핵심 개념을 한 문장으로 알려줘."},
    {"role": "assistant", "content": "쿠버네티스는 컨테이너화된 애플리케이션의 자동 배포, 스케일링 및 관리를 제공하는 오픈소스 오케스트레이션 플랫폼입니다."},
    {"role": "user", "content": "그렇다면 도커(Docker)와의 가장 큰 차이점은 무엇인가요?"}
]

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages,
    temperature=0.7,
    max_tokens=200
)
print("=== Chat Completion 응답 ===")
print(response.choices[0].message.content)

# 2. 문장 교정 및 윤문 실습
proofread_prompt = """다음 문장의 맞춤법을 교정하고, 전문적인 비즈니스 이메일 톤으로 수정해 주세요.
원문: '프로젝트 일정이 쫌 늦어져서 내일까지 보내드리기 힘들꺼가타요 죄송해요'"""

proof_res = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "당신은 비즈니스 커뮤니케이션 교정 전문가입니다."},
        {"role": "user", "content": proofread_prompt}
    ],
    temperature=0.2
)
print("\n=== 비즈니스 교정 결과 ===")
print(proof_res.choices[0].message.content)
```

## 4. 인터랙티브 멀티 턴 대화 컨텍스트 토큰 누적 시뮬레이터

대화 턴(Turn)이 진행될 때마다 전체 메시지 히스토리가 매 요청마다 재전송되면서 소비되는 토큰량과 비용의 지수적 증가를 실시간으로 확인한다.

(function() {
  var sTurn = document.getElementById('chat-turn-slider');
  var vTurn = document.getElementById('chat-turn-val');
  var tLast = document.getElementById('chat-last-tok');
  var tCum = document.getElementById('chat-cum-tok');
  var tCost = document.getElementById('chat-cost-txt');

  function render() {
    var k = parseInt(sTurn.value, 10);
    vTurn.textContent = k + ' 턴 (총 ' + (k * 2 + 1) + '개 메시지)';

    // 시스템 프롬프트: 50 토큰, 턴당 유저 80 토큰 + 어시스턴트 120 토큰 = 200 토큰/턴
    var sysTok = 50;
    var turnTok = 200;

    var lastTok = sysTok + (k - 1) * turnTok + 80;
    var cumTok = 0;
    for (var i = 1; i <= k; i++) {
      cumTok += (sysTok + (i - 1) * turnTok + 80 + 120);
    }

    tLast.textContent = lastTok.toLocaleString() + ' 토큰';
    tCum.textContent = cumTok.toLocaleString() + ' 토큰';

    var cost = (cumTok / 1000000) * 0.30;
    tCost.textContent = '$ ' + cost.toFixed(5);
  }

  sTurn.addEventListener('input', render);
  render();
})();
</script>
