> [!abstract] 핵심
> 자연어 시퀀스를 임베딩으로 바꾸고 RNN·LSTM으로 다음 요소 또는 전체 시퀀스를 예측하는 실습의 흐름을 정리한다.

## 문제를 모델로 바꾸기

자연어 토큰은 그대로 수치 연산할 수 없으므로 임베딩으로 변환한다. RNN은 시간 순서에 따라 은닉 상태를 갱신하고, LSTM은 장기 정보를 유지하는 구조를 사용한다. 실습에서는 예측된 전체 시퀀스와 정답 시퀀스의 차이로 손실을 계산한다.

```mermaid
flowchart LR
    A["입력 또는 관찰"] --> B["표현과 전처리"]
    B --> C["학습 규칙"]
    C --> D["예측 또는 판단"]
    D --> E["검증과 해석"]
```

| 관점 | 이 노트에서 확인할 질문 | 학습할 때의 점검 |
| --- | --- | --- |
| 임베딩 | 토큰을 조밀한 벡터로 변환 | 어휘 사전과 벡터 차원을 일관되게 둔다 |
| 순환 처리 | 순서에 맞게 상태를 전달 | 입력과 정답의 시간 축을 맞춘다 |
| 시퀀스 손실 | 예측 전체와 정답 전체 비교 | 길이·마스킹·평가 단위를 기록한다 |

> [!note] 흐름
> 입력·정답 시퀀스를 같은 규칙으로 준비하고, 어휘 표현과 길이 처리를 결정한다. 모델의 출력 차원과 손실의 비교 단위가 맞는지 확인한 뒤 RNN과 LSTM의 학습 변화를 비교한다.

## 관점을 나누어 보기

<Tabs>
<Tab label="개념">

실습의 출발점은 자연어를 벡터로 바꾸는 것이다. 임베딩은 순서 자체가 아니라 각 토큰의 수치 표현을 제공한다.

</Tab>
<Tab label="실행">

RNN·LSTM 모두 시퀀스 입출력 모양을 확인해야 한다. 모델이 낸 모든 시점의 출력을 어떻게 정답과 대응시킬지 명시한다.

</Tab>
<Tab label="검증">

훈련 손실이 감소해도 새로운 문장 조각에서 같은 품질이 보장되지는 않는다. 길이와 표현이 다른 입력을 따로 점검한다.

</Tab>
</Tabs>

> [!tip] 학습 전략
> 입력, 모델의 가정, 평가 기준을 한 문장씩 연결해 설명해 본다. 계산 결과만 적지 말고 어떤 선택이 결과를 바꾸는지도 기록한다.
> [!warning] 해석 주의
> 시퀀스의 패딩이나 길이 차이를 손실 계산에서 다루지 않으면, 실제 토큰 예측과 무관한 값이 평가를 흔들 수 있다.
