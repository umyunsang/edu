> [!abstract] 한 줄 요약
> 지시문 파인튜닝의 품질은 데이터 양보다, **무슨 지시·입력·응답을 남기고 무엇을 걸러냈는가**에 좌우된다.

강의는 적은 사람이 만든 시드 예시에서 새 지시문 데이터를 반복 생성·필터링하는 Self-Instruct 흐름과, 대화 데이터를 활용한 오픈소스 챗봇 사례를 소개한다. 두 사례 모두 “모델을 학습시킬 문장을 어떻게 설계할 것인가”가 중심이다.

## 한 학습 예시의 구조

| 필드 | 의미 | 품질 질문 |
| :-- | :-- | :-- |
| 지시문 | 모델이 해야 할 일을 설명 | 작업 경계가 분명한가 |
| 입력 | 작업에 필요한 맥락·자료 | 답에 필요한 정보가 충분한가 |
| 응답 | 기대하는 결과 형식과 내용 | 사실성·안전성·표현 형식이 적절한가 |

> [!important] 데이터의 역할은 행동을 가르치는 것
> 지시문 데이터는 단순한 문장 모음이 아니다. 어떤 요청에 어떤 형식·톤·추론 경로로 반응해야 하는지 보여 주는 행동 예시다.

## 생성과 필터링

<Tabs>
  <Tab label="시드 작성">
    사람이 만든 소수의 고품질 예시로 작업 범위와 응답 형식을 정한다. 작은 시드라도 다양성과 정확성이 중요하다.
  </Tab>
  <Tab label="후보 확장">
    모델을 이용해 새 지시·입력·응답 후보를 만든다. 자동 생성은 속도를 높이지만 품질 보증을 대신하지 않는다.
  </Tab>
  <Tab label="필터링">
    중복, 불완전한 지시, 모순된 응답, 목표에서 벗어난 사례를 제거한다. 이 단계가 학습 집합의 성향을 결정한다.
  </Tab>
</Tabs>

대화 기반 파인튜닝은 답변 문장뿐 아니라 맥락을 따라가는 방식을 학습시킨다. 따라서 사용자 발화와 모델 응답의 경계, 개인정보와 민감한 내용, 부정확한 답의 혼입을 점검해야 한다.

<details>
<summary>지시문 데이터 검토 체크리스트</summary>

- 서로 다른 예시가 실제로 서로 다른 작업을 다루는가
- 입력 없이도 답할 수 있는 지시와, 입력이 필수인 지시가 구분되는가
- 응답에 근거 없는 단정·개인정보·유해한 요청 수용이 들어 있지 않은가
- 원하는 답변 길이·형식·언어가 일관되게 정의되었는가
- 학습용과 평가용 예시가 섞이지 않았는가

</details>

> [!warning] 원문 표기 오류
> 강의 추출문에는 Self-Instruct를 가리키는 단어가 두 차례 잘못 표기되어 있다. 이 노트에서는 통용 표기인 **Self-Instruct**로 바로잡아 사용한다.

## 핵심 정리

| 개념 | 기억할 점 |
| :-- | :-- |
| 시드 데이터 | 자동 확장의 방향을 정하는 고품질 출발점 |
| Self-Instruct | 모델로 후보 지시문을 만들고 필터링해 데이터를 확장 |
| 대화 파인튜닝 | 다중 턴 맥락과 역할별 응답 형식을 학습 |
| 필터링 | 중복·오류·목표 이탈을 줄이는 핵심 단계 |
| 데이터 거버넌스 | 개인정보·동의·재사용 가능성을 함께 확인 |

> [!question]- 스스로 점검
> 자동 생성한 지시문 데이터를 그대로 학습에 쓰면 왜 문제가 되는가?
>
> **답:** 생성 모델은 중복·모순·부정확한 답을 만들 수 있다. 필터링 없이 누적하면 그 성향이 학습 데이터와 모델 응답에 함께 굳어진다.
