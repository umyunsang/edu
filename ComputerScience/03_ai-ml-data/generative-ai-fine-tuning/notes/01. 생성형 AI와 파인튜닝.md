> [!abstract] 한 줄 요약
> 생성형 AI는 결과물을 만드는 모델이고, 파인튜닝은 그 모델의 **표현 경향을 특정 목적에 맞춰 조정하는 학습**이다.

이 과정의 출발점은 “어떤 도구가 유행하는가”가 아니라, 이미 폭넓게 학습된 생성 모델을 디자인 작업에 어떻게 연결할 것인가이다. 텍스트·이미지·영상처럼 결과 매체는 달라도, 입력을 해석하고 출력 분포를 만든다는 공통 구조를 가진다.

## 생성형 AI의 공통 구조

| 요소 | 역할 | 디자인 작업에서의 질문 |
| :-- | :-- | :-- |
| 입력 | 모델에 의도와 조건을 전달 | 무엇을 만들고, 무엇을 피할 것인가 |
| 사전학습 모델 | 넓은 데이터에서 배운 일반 패턴을 제공 | 이미 가능한 범위는 어디까지인가 |
| 조정 방식 | 프롬프트·참조·추가 학습으로 출력을 바꿈 | 일회성 지시인가, 반복 가능한 성향인가 |
| 출력 | 텍스트·이미지·영상·코드 등 결과물 | 검토 가능한 품질 기준을 만족하는가 |

> [!note] 매체가 달라도 판단은 같다
> 대화형 텍스트, 스타일 이미지, 짧은 영상은 서로 다른 결과물이다. 그러나 모두 입력 조건과 모델의 기존 능력 사이에서 출력이 결정되므로, 목표·데이터·검토 기준을 분리해 정의해야 한다.

## 프롬프트와 파인튜닝의 구분

<Tabs>
  <Tab label="프롬프트">
    한 번의 요청에 조건을 적는 방식이다. 빠르게 실험할 수 있고, 모델 자체의 가중치는 바꾸지 않는다. 요구가 매번 달라지거나 탐색 단계일 때 적합하다.
  </Tab>
  <Tab label="파인튜닝">
    목적과 관련된 데이터로 추가 학습해 특정 스타일·지시·도메인 반응을 더 일관되게 만들려는 방식이다. 데이터 선택과 평가가 핵심이 된다.
  </Tab>
  <Tab label="함께 쓰기">
    파인튜닝 후에도 프롬프트는 필요하다. 추가 학습은 기본 경향을 조정하고, 프롬프트는 한 결과물의 구도·내용·제약을 지정한다.
  </Tab>
</Tabs>

## 멀티미디어 작업에서의 흐름

```mermaid
flowchart LR
    A["목적 정의"] --> B["입력 자료 정리"]
    B --> C["모델과 조정 방식 선택"]
    C --> D["생성 결과 검토"]
    D --> E["수정 또는 재학습"]
    E --> C
```

## 파인튜닝 전에 답할 질문

1. 결과물에서 반복되어야 하는 특징은 무엇인가?
2. 그 특징을 설명하는 것만으로 충분한가, 아니면 예시 데이터가 필요한가?
3. 데이터는 원하는 속성만 담고 있는가?
4. 원하는 변화와 원하지 않는 변화는 어떻게 구분해 평가할 것인가?
5. 결과가 한 번 좋아 보이는 것과 일관되게 재현되는 것을 어떻게 구분할 것인가?

<details>
<summary>작업 요청을 학습 목표로 바꾸는 간단한 틀</summary>

- **대상**: 어떤 종류의 텍스트·이미지·영상 결과를 만들 것인가
- **유지할 속성**: 브랜드 톤, 소재, 색감, 구도처럼 반복되어야 하는 특징은 무엇인가
- **바꿀 속성**: 요청마다 달라져야 하는 내용은 무엇인가
- **검토 기준**: 누가 무엇을 보고 통과·수정·폐기를 결정하는가

이 네 항목이 비어 있으면 데이터가 많아도 파인튜닝 목표는 모호하다.

</details>

> [!important] 핵심 원칙
> 파인튜닝은 “더 많은 생성”을 보장하는 버튼이 아니다. 일반 모델이 가진 능력 중에서 어떤 반응을 더 쉽게 꺼내고 싶은지 정하는 **목적 정렬 작업**이다.

## 핵심 정리

| 개념 | 기억할 점 |
| :-- | :-- |
| 생성형 AI | 입력 조건에 맞는 새 결과물을 만드는 모델군 |
| 사전학습 | 넓은 일반 패턴을 미리 학습한 상태 |
| 프롬프트 | 한 요청의 조건을 지정하는 방법 |
| 파인튜닝 | 특정 목적에 맞는 반응 경향을 추가 학습으로 조정하는 방법 |
| 평가 | 결과가 의도와 제약을 반복해서 만족하는지 확인하는 과정 |

> [!question]- 스스로 점검
> 같은 스타일을 여러 작업에서 반복해야 할 때, 먼저 프롬프트 실험을 해야 하는 이유는 무엇인가?
>
> **답:** 실제로 반복되어야 할 특징과 프롬프트만으로 해결되는 범위를 먼저 확인해야, 불필요한 추가 학습과 잘못된 데이터 수집을 피할 수 있기 때문이다.
