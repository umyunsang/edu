YAML
설정 가이드
GUIDE

Label 이름 매핑
YAML 파일의 최상위 키(Key)가 자동으로 GitHub Label 이름이 됩니다.
(예: frontend , backend )

Glob 패턴 활용
**/* 패턴을 사용하여 하위 디렉토리의 모든 변경사항을 감지합니다. 특정
확장자만 타겟팅할 수도 있습니다.

자동 분류 원리
Pull Request가 생성되거나 업데이트될 때, 변경된 파일 목록을 스캔하여
일치하는 규칙의 레이블을 자동으로 부착합니다.

주의사항
해당 Label이 저장소에 미리 생성되어 있어야 오류 없이 동작합니다. 파일
위치는 반드시 .github/labeler.yml 이어야 합니다.
# .github/labeler.yml 설정 파일
documentation:
  - docs/**/*
  - '**/*.md'
frontend:
  - 'src/components/**/*'
  - 'src/pages/**/*'
backend:
  - 'src/api/**/*'
  - 'src/services/**/*'
tests:
  - '**/*.test.js'
  - '**/*.spec.js'

Label 자동화 Workflow
GitHub Actions를 활용하여 PR 생성 시 자동으로 레이블을 부착하는 설정
.github/workflows/labeler.yml
YAML
설정 포인트
INFO
name: Labeler
on: # Trigger condition
  - pull_request_target
jobs:
  triage:
    permissions:
      contents: read
      pull-requests: write
    runs-on: ubuntu-latest
    
    steps:
    - uses: actions/labeler@v4
      with:
        repo-token: "${{ secrets.GITHUB_TOKEN }}"
        sync-labels: true
        # configuration-path: .github/labeler.yml (default)
on: pull_request_target
Fork된 저장소의 PR에서도 안전하게 동작하기 위해 `pull_request`
대신 사용합니다. 원본 저장소의 권한 컨텍스트에서 실행됩니다.
permissions 설정
GitHub Actions 봇이 PR에 레이블을 추가하기 위해 `pull-
requests: write` 권한이 명시적으로 필요합니다.
actions/labeler@v4

Cumulative Flow Diagram (CFD)
작업의 상태별 누적 흐름을 통해 병목 현상과 진행 속도를 시각화
차트 해석 방법
가로축은 시간, 세로축은 작업의 누적 개수를 나
타냅니다. 각 영역의 너비(수직 높이)는 해당 단
계에 머물러 있는 작업(WIP)의 양을 의미합니다.
병목 발견
특정 상태의 영역이 급격히 넓어지면 해당 단계
의 처리 속도가 느려져 작업이 쌓이고 있다는 뜻
입니다. (예: Review 단계의 비대화)
리드 타임 예측
그래프의 수평 너비는 작업이 시작되어 완료되기
까지 걸리는 평균 시간(Lead Time)을 나타냅니
다.

# GitHub GraphQL API로 완료된 이슈 수집
query($owner: String!, $repo: String!) {
  repository(owner: $owner, name: $repo) {
    issues(first: 100, states: CLOSED) {
      nodes {
        title
        createdAt
        closedAt
        labels(first: 10) {
          nodes {
            name
          }
        }
      }
    }
  }
}
// 수집된 데이터를 바탕으로 Cycle Time 계산
const issues = data.repository.issues.nodes;
// 각 이슈별 소요 시간(일 단위) 계산
const cycleTime = issues.map(issue => {
  const created = new Date(issue.createdAt);
  const closed = new Date(issue.closedAt);
  
  // 밀리초 -> 일 단위 변환
  return (closed - created) / 
    (1000 * 60 * 60 * 24);
});
// 전체 평균 Cycle Time 도출
const avgCycleTime = cycleTime.reduce((a, b) => a + b) 
  / cycleTime.length;
console.log(`Average Cycle Time: ${avgCycleTime.toFixed(1)} days`);
