# Wave 1 Web: Public LinkedIn Post Patterns

## Key Findings

- Real LinkedIn project posts commonly use one sharp hook, short paragraphs, one concrete artifact, and a direct but non-generic CTA.
- Common shapes observed:
  - Problem → what I built → how it works → link/feedback ask.
  - Realization → artifact → reusable lesson → question.
  - Claim → proof/list → takeaway.
- Korean developer posts frequently open with a clear story or concrete claim, then use numbered or arrow-style blocks to explain what changed.
- Heavy hashtag stacks read as growth hacking. Examples often use 0-3 hashtags.
- Links are acceptable when they are the artifact, but should be direct, not broad repository roots.

## Sources

- LinkedIn public post, Neo Kim system design repo: direct "I built a GitHub repo" hook, bullet list of contents, PS CTA to star/save/repost.
- LinkedIn public post, Matt Nigh Copilot issue templates: describes what the repo does, practical uses, MIT license, numbered usage steps, link.
- LinkedIn public post, RepoFit: starts with a practical problem, positions scope explicitly, lists questions it answers, asks for feedback/stars.
- Korean LinkedIn public post, portfolio template: personal motivation, what was built, what was removed/simplified, reflective question about non-developer usability.
- Korean LinkedIn public post, claude-sisyphus-grad: GitHub link first, "자는 동안 실험을 돌려주는 AI 대학원생" hook, explains workflow and boundary.

## EXPAND

- LEAD: Korean developer "problem → built artifact → operational detail" pattern — WHY: directly applicable to the user's Korean LinkedIn drafts — ANGLE: rewrite each post around one concrete problem and proof.
- LEAD: One artifact per post — WHY: real examples rarely make readers choose between five equal links — ANGLE: primary link in body, secondary links as optional comment.
- LEAD: Soft CTA for Korean audience — WHY: "repost/follow" can feel too promotional — ANGLE: ask a real workflow question instead.
