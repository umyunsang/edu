Toward Tabular Foundation Models
• Can we build a tabular foundation model that can transfer across 
many tables and tasks?
• Why is this difficult?
• Tables are highly heterogeneous
• Unlike text, tabular tasks are not naturally standardized
• Large-scale training requires unifying many tables into a common format
• Two directions:
• LLM-based tabular foundation models
• TabPFN-style foundation models ← this lecture

TabPFN v1: Applying PFNs to Tables
5
• Key Idea: A PFN for tabular prediction
• Each row is treated as one token:
• A training datapoint: 𝑥, 𝑦↦MLP𝑥𝑥+ MLP𝑦𝑦
• A test input: 𝑥↦MLP𝑥𝑥+ MLP𝑦[mask]
• Zero-padding handles different numbers of columns
Hollmann et al., TabPFN: A Transformer That Solves Small Tabular Classification Problems in a Second, ICLR 2023



### [Page 6]
TabPFN v1: Applying PFNs to Tables
6
• Key Idea: A PFN for tabular prediction
• TabPFN Transformer architecture:
• Transformer processes all train/test row tokens together
• Self-attention allows test samples to attend to training samples
• Final hidden state of each test token is passed to an MLP classifier
Hollmann et al., TabPFN: A Transformer That Solves Small Tabular Classification Problems in a Second, ICLR 2023

### [Page 8]
TabPFN v1: Applying PFNs to Tables
8
• Key Idea: A PFN for tabular prediction
• Transformer architecture
• Synthetic priors for tabular data
• Why It works?
• The synthetic prior is rich enough to cover most real datasets approximately
• Transformers are flexible enough function approximators to learn the 
Bayesian posterior for that prior
• Full row-attention lets the model adapt instantly to new training data
Hollmann et al., TabPFN: A Transformer That Solves Small Tabular Classification Problems in a Second, ICLR 2023

### [Page 10]
TabPFN v1: Limitations
10
Hollmann et al., TabPFN: A Transformer That Solves Small Tabular Classification Problems in a Second, ICLR 2023
• Do not consider 2D structure of tabular data
• TabPFN v1 treats each row as a single token
• Model constraints
• Less than 1K training samples and 100 columns
• Multiclass classification with less than 10 classes
• Require manual preprocessing for missing and categorical values 



### [Page 11]
TabPFN v2 
• Key change #1: From Row Tokens to 2D Table Modeling
• Represent each cell as one token to better handle 2D tabular structure and 
feature heterogeneity
• Apply 2D attention: feature-wise & sample-wise attention alternatively
11
Hollmann et al., Accurate predictions on small data with a tabular foundation model, Nature 2025



### [Page 12]
TabPFN v2 
• Key change #2: Richer Synthetic Prior
• TabPFN v2 is trained on synthetic tasks that better reflect real-world tables
• Synthetic task components: categorical features, missing values, quantization, …
• Datasets up to 10,000 samples and 500 features
12
Hollmann et al., Accurate predictions on small data with a tabular foundation model, Nature 2025



### [Page 13]
TabPFN v2 
• TabFPN v2 outperforms MLP and GBDT baselines on small datasets

### [Page 14]
TabPFN v2: Limitations
• Computational cost
• Cell-level representations and two-way attention increase inference cost
• Memory scalability
• Processing larger context tables requires more memory
• Task scale
• Classification evaluation is limited to tasks with up to 10 classes
14
Hollmann et al., Accurate predictions on small data with a tabular foundation model, Nature 2025

### [Page 19]
Summary: TabPFN-v1, v2, and v3
• Evolution of TabPFN
• v1: Synthetic pretraining enables in-context prediction for small tabular tasks
• v2: Table-aware modeling improves performance on realistic tables
• v3: Efficient row-level ICL scales the paradigm to much larger datasets
• Recent Research Directions
• Make tabular ICL more scalable and efficient
• Improve pretraining with richer synthetic priors or real-world data
• Extend TabPFN to semantically rich and heterogeneous tables
Next: Recent TabPFN variants

### [Page 20]
TabDPT
• Main Idea: Using similar rows as context leads to better ICL 
prediction than using the full dataset and scalability
• Method
• Treat each row as a single token (similar to TabPFN v1)
• Retrieve the K most similar rows as context for ICL prediction
• Pretrain on real-world tabular data with masked column SSL 
20
Ma et al., TabDPT: Scaling Tabular Foundation Models on Real Data, NeurIPS 2025

### [Page 24]
TabICL
• Motivation: TabPFN-v2's alternating row/column attention becomes 
costly on large tables
• Method: Compress feature information into fixed-dimensional row 
embeddings, then perform ICL over rows
24
Qu et al., TabICL: A Tabular Foundation Model for In-Context Learning on Large Data, ICML 2025

### [Page 40]
Open Directions for Tabular FMs
• Scalability and Efficiency
• Million-scale inference is becoming possible, but memory, latency, and long-
context processing remain important bottlenecks
• Pretraining Distribution
• Richer synthetic priors and real-world tables provide complementary signals 
for better generalization
• Semantic and Heterogeneous Tables
• Column names, textual values, missingness, and mixed feature types remain 
underexplored sources of information
• Beyond Standard Flat Tables
• Relational, temporal, multimodal, and causal settings remain promising 
directions for future research
