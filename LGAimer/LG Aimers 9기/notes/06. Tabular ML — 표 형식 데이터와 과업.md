## 단계별 정리

### 표 형식의 구조

- 각 행은 하나의 관측·레코드·인스턴스이며 열은 feature·attribute다.
- 수치·범주·이진·날짜시간·자유 텍스트가 한 행에 함께 있을 수 있다.
- 이미지·텍스트와 달리 고정된 공간·순차 구조가 없는 경우가 많다.

### 현실적 난점

- 수천 행에서 수천 열까지 작은 중간 규모 데이터가 흔하다.
- 센서 실패·미응답·다중 출처 때문에 결측값이 자주 생긴다.
- 라벨 노이즈·시간에 따른 규칙 변화·불균형 클래스가 모델링을 어렵게 한다.

### 과업 지도

- 지도 예측은 회귀·분류로 나뉘며 새 레코드의 target을 추정한다.
- 이상 탐지는 정상 데이터에서 드문 레코드를 찾고, 클러스터링은 숨은 그룹을 발견한다.
- Table QA는 자연어 질문을 필터·집계·추론으로 변환하고, 합성 생성은 통계적 성질을 보존한다.

### ML 파이프라인

- 신뢰할 수 있는 데이터 수집과 테이블 결합으로 시작한다.
- EDA에서 요약 통계·결측 패턴·분포를 확인한다.
- 전처리·모델링·평가 뒤 배포와 모니터링으로 이어진다.

### 모델 선택 질문

- 표 데이터는 이질적이고 domain knowledge가 제한될 수 있어 모델 선택이 과업 의존적이다.
- 작은 데이터에서는 강한 baseline과 결측·불균형 대응이 특히 중요하다.
- 나중의 deep·LLM·foundation model 비교를 위해 데이터 구조와 파이프라인을 먼저 고정한다.

| 단계 | 원본에서 관찰할 신호 | 학습 산출물 |
| --- | --- | --- |
| 구조 | 행·열·혼합 타입 | 입력 스키마 |
| 난점 | 결측·노이즈·불균형 | 전처리·평가 |
| 과업 | 예측·탐지·클러스터·QA·생성 | target·출력 |
| 운영 | 수집→EDA→모델→배포 | 모니터링 |

> [!warning] 읽을 때의 주의점
> 강의는 표 데이터의 일반적 특성을 제시한다. 특정 도메인의 결측 처리나 최적 모델을 자동으로 결정해 주는 규칙은 아니다.
