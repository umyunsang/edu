MPI란

▪분산 메모리형 병렬 컴퓨터에서의 병렬 프로그래밍을 위한 프로세서 간 통신 라이브러리

▪기본 언어(FORTRAN/C/C++)에 프로세서 간 통신을 하는 서브 루틴/함수를 추가하여 병렬 프로그래밍을 할

수 있도록 확장

▪1992년경부터 미국 컴퓨터 제조업체 및 대학을 중심으로 표준화

▪MPI의 규격

➢1995 MPI: Message Passing Interface Standard

➢1997 MPI2: Extensions to the Message Passing Interface

➢2012 MPI3.0
분산 메모리 병렬 계산기(복습)

⚫아키텍처

▪각기 메모리를 가진 여러 개의 PU를 네트워크로 연결
▪각 PU는 각각 자신이 가진 메모리에만 접근 가능

⚫특징

➢수천~수만 PU 규모의 병렬 처리 가능
➢PU 간 데이터 분산을 의식한 프로그래밍 필요

⚫프로그래밍 언어

➢FORTRAN/C/C++ + MPI 사용

MPI 프로그램의 구성요소

원본 프로그램

➢일반적인 FORTRAN 또는 C/C++로 작성된 프로그램

➢분산 메모리를 의식하여 작성되어야 한다.

환경 설정 및 환경 획득을 위한 함수

➢MPI의 초기화, 종료 처리를 하는 함수

➢자기 프로세스의 Rank(고유식별자), 전체 프로세스 수를 취득하는 함수

통신 함수

➢프로세스 간 통신을 위한 서브 루틴/함수

➢일대일 통신과 집단 통신이 있다.

기본 데이터 타입과 미리 정의된 연산

➢MPI_INT, MPI_FLOAT, MPI_DOUBLE, MPI_CHAR 등

➢통신 함수의 데이터 타입 지정 및 통신과 연산을 동시에 수행하는 함수(합산 등)의 연산 지정에 이용한다.

인클루드 파일

➢프로그램 시작 부분에 #include <mpi.h>라고 기술한다.

실행 시 지정

➢mpirun 명령어로 프로그램 실행에 사용할 프로세스 수를 지정한다.

## --- [Page 18] ---
프로그램 설명

MPI_Init 및 MPI_Finalize

➢프로그램의 시작과 끝에서 호출하여 각각 MPI 초기화, 종료 처리를 수행한다.

int MPI_Comm_size(MPI_Comm comm, int *nprocs)

➢comm은 프로세스 그룹을 지정하는 커뮤니케이터

✓MPI_COMM_WORLD로 하면 모든 프로세스를 포함하는 그룹을

의미한다.

➢comm 내의 모든 프로세스 수가 nprocs에 들어간다.

➢성공하면 MPI_SUCCESS가 함수 값으로 반환된다.

int MPI_Comm_rank(MPI_Comm comm, int *myrank)

➢comm 내의 자신의 프로세스 번호가 myrank에 들어간다.

이 함수들은 어떤 MPI 프로그램에서도 샘플 프로그램과 같은 순서로 호출하면 된다.

MPI 프로그램(데이터 교환)

•
데이터 교환에서 중요한 것은 ① 송신(send), ②수신(Recv), ③대기(Wait) 세 가지.

•
MPI에서는 송신과 수신이 일치하지 않으면 통신이 되지 않음.

•
따라서 프로그램이 잘 흘러가도록 머리로 생각하면서 적절한 위치에 명령을 배치해야 함.

•
만약 실수로 인해 서로가 수신 대기 상태가 되면 처리가 전혀 진행되지 않는 '데드락(Deadlock)'이라는 현상

이 발생하게 됨

•
데이터를 다른 프로세스로 보내기 위한 API로 MPI_Send와 MPI_ISend가 있다.

•
MPI_Send는 송수신이 확정될 때까지 대기하는 Blocking 통신이다.

✓프로그램의 흐름에 따라 순서대로 실행되기 때문에 예상치 못한 일이 발생하기 어렵다는 특징이 있다.

•
반면 MPI_ISend는 송신 명령을 내리면서 다음 처리를 진행하는 Non-Blocking 통신이다.

✓대기 시간이 없어 효율적이지만, 예상치 못한 데이터 업데이트가 발생하지 않도록 MPI_Wait를 통해 동

기화 타이밍을 적절히 부여해야 한다.

⚫전송(Send)

int ar[10]; MPI_Send(ar, 10, MPI_INT, 1, 0, MPI_COMM_WORLD);

MPI_Send의 인수는 왼쪽부터 순서대로 '보내고자 하는 배열의 시작 주소', '요소 수', '타입', '수신 측의 랭크

•
이를 통해 랭크 1의 프로세스에 대해 배열 ar을 전송할 수 있다.

프로세스 0
프로세스 1

⚫대기(Wait)

•
블로킹 통신을 사용하든 비블로킹 통신을 사용하든, 노드 간 진행을 일치시키고 싶을 때가 있다.

•
예를 들어, 모든 데이터가 다 모인 후에 진행을 하고 싶을 때, 프로세스 3, 4가 따라잡을 때까지 프로세스 1,

2를 기다리게 하고 싶을 때가 있다.

•
이를 해결하기 위해 사용하는 것이 '동기화'입니다. 동기화를 통해 다른 프로세스를 기다릴 수 있다.

프로세스1 프로세스2
프로세스4
프로세스3

동기

## --- [Page 33] ---

동기화

•
모든 노드를 동기화하려면 아래의 MPI_Barrier를 사용.
•
MPI_Barrier(MPI_COMM_WORLD);
•
이를 송수신 뒤에 넣으면 노드들의 진행을 동기화할 수 있다.
•
비블로킹의 경우 Wait 또는 Waitall을 사용한다. 이들은 지정된 요청만 동기화할 수 있다.
•
Waitall은 다음과 같이 사용함.

MPI_Request send_request, recv_request; 
・・・ 
MPI_Isend(・・・, &send_request); 
MPI_Irecv(・・・, &recv_request); 
MPI_Waitall(1, &send_request, MPI_STATUS_IGNORE); 
MPI_Waitall(1, &recv_request, MPI_STATUS_IGNORE);

•
위 프로그램에서는 첫 번째 Waitall에서 모든 노드의 Isend를 기다리고, 두 번째 Waitall에서 모든 노드의 
Irecv를 대기.
•
MPI_Waitall의 인수는 왼쪽부터 순서대로 ＇요청 개수＇, ＇요청의 시작 주소＇, ＇상태'이다.
•
요청은 Isend나 Irecv의 끝에 붙이는 식별자를 의미하며, 이들과 대응한다.
•
상태는 기본적으로 MPI_STATUS_IGNORE를 사용하면 된다.
•
하지만 위의 경우 Waitall을 두 번 작성해야 하므로 번거롭습니다. 그래서 배열을 사용하여 Waitall을 단축해 
보자.
