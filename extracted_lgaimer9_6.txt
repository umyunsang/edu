### [Page 3]
Why Representation Learning?
• Motivation: Learn from limited labels and abundant unlabeled data
• Labels are often expensive, scarce, or noisy
• Unlabeled tables can be abundant and easier to collect
• Challenge: Learning meaningful representations from tables
• Heterogeneous features: numerical, categorical, binary, and missing values
• No universal spatial or sequential structure unlike images or text
• Diverse domains with domain-specific semantics
• No universal augmentation strategy for tabular data
How can we learn useful representations from unlabeled tables 
while preserving their semantics?

### [Page 5]
Learning from Unlabeled Tables
• Self-supervised learning learns representations without task labels
• Create a pretext task from unlabeled data
• Pre-train an encoder using the pretext task
• Fine-tune the learned representation for downstream prediction
• The representation quality depends on the design of the pretext task
Key Question
What self-supervised task is appropriate for tabular data?

### [Page 6]
VIME: Reconstruction-Based SSL
• Key Idea: Corrupt tabular inputs and train the model to recover
• Randomly mask some features & replace masked values by other rows
• Two Pretext Tasks
• Mask estimation: Which features were corrupted?
• Value imputation: What were the original feature values?
VIME learns representations by identifying and restoring corrupted feature values
6
Yoon et al., VIME: Extending the Success of Self- and Semi-supervised Learning to Tabular Domain, NeurIPS 2020



### [Page 7]
VIME: Intuition and Limitation
• Why can it work?
• To reconstruct missing or corrupted features, the model must learn 
dependencies among columns
• E.g., occupation, income, and education may help predict one another
• Practical extension
• VIME also uses unlabeled samples in a semi-supervised learning framework
• Limitations
• Depends on whether corruption creates a meaningful learning task
• Arbitrary value replacement may produce unrealistic samples
7
Yoon et al., VIME: Extending the Success of Self- and Semi-supervised Learning to Tabular Domain, NeurIPS 2020

### [Page 9]
From Recon. to Contrastive Learning
• Reconstruction vs Contrastive Learning:
• Reconstruction: Can the model recover corrupted inputs?
• Contrastive learning: Can the model recognize two related views?
• Goal of Contrastive Learning
• Pull together representations of related views
• Separate representations of different samples
• Key Question: How should two views of a tabular row be generated?
• This view construction is the central problem for tabular contrastive learning
9



### [Page 10]
SubTab: Views from Feature Subsets
• Key Idea: Treat different subsets of columns as multiple views of the 
same row
• Each subset represents partial information about the same sample
• Learn representations that are consistent across subsets
Useful representations should capture information shared across partial views
10
Ucar et al., SubTab: Subsetting Features of Tabular Data for Self-Supervised Representation Learning, NeurIPS 2021



### [Page 11]
SCARF: Views from Feature Corruption
• Key Idea: Create a positive view by randomly corrupting a subset of 
features
• Replace a feature with values sampled from their marginal distributions
• Treat the original and corrupted rows as a positive pair
A simple and general strategy for contrastive tabular pre-training
11
Bahri et al., SCARF: Self-Supervised Contrastive Learning using Random Feature Corruption, ICLR 2022



### [Page 12]
SAINT: Views from CutMix & Mixup
• Key Idea: Create a positive view by CutMix & Mixup augmentations
• Use CutMix-style feature replacement to mix feature values across samples
• Use Mixup-style interpolation in the embedding space
• Additional contribution: architecture with intersample attention
CutMix and Mixup-style augmentations for tabular SSL
12
Somepalli et al., SAINT: Improved Neural Networks for Tabular Data via Row Attention and Contrastive Pre-Training, 2021



### [Page 13]
What Have We Learned So Far?
• Why combine reconstruction and contrastive learning?
• Reconstruction encourages the model to learn feature dependencies
• Contrastive learning encourages stable representations across different views
• Both are useful because each feature may carry task-critical semantics
• Early tabular SSL methods rely on manually-designed input-level 
augmentations
• E.g., corruption, mask, replace, mix, or subset features
• Common Assumption: Modified views should preserve the essential 
meaning of the original row
13



### [Page 14]
Beyond Input-Level Augmentations
• Why Move Beyond Input-Level Augmentation?
• Input-level augmentation remains difficult for tabular data
• Removing features may discard task-relevant information
• Replacing values may create unrealistic rows
• Valid transformations vary across domain
Recent tabular SSL methods seek learning signals that are less 
dependent on hand-designed input corruption
• Recent Direction:
• Do not directly modify raw feature values
• Instead, manipulate or predict representations in latent space
14



### [Page 15]
RaTab: Augmentation in Latent Space
• Key Idea: Modify the encoder to generate alternative views instead 
of modifying raw feature values
• Apply truncated SVD to the final-layer weight matrix of the encoder
• Construct an augmented encoder using the truncated weights
• Use both reconstruction and contrastive losses
15
Eo et al., Representation Space Augmentation for Effective Self-Supervised Learning on Tabular Data, AAAI 2025



### [Page 16]
RaTab: Augmentation in Latent Space
• RaTab pretraining improves performance of various architectures
• Evaluation protocol: RaTab pretraining → supervised fine-tuning
16
Eo et al., Representation Space Augmentation for Effective Self-Supervised Learning on Tabular Data, AAAI 2025



### [Page 17]
T-JEPA: Augmentation-Free Tabular SSL
• Key Idea: Predict one latent feature view from another, rather than 
reconstructing corrupted inputs
• Predict a target feature subset from a context subset in latent space
• Use feature masking only; no input-level augmentation required
17
Thimonier et al., T-JEPA: Augmentation-Free Self-Supervised Learning for Tabular Data, ICLR 2025



### [Page 18]
T-JEPA: Augmentation-Free Tabular SSL
• T-JEPA learns useful representations for tabular prediction 
• Evaluation protocol: T-JEPA pretraining → training on learned representations
18

+ What is JEPA?
• Joint-Embedding Predictive Architecture (JEPA)
• A self-supervised learning framework that learns to predict (or generate) 
latent in embedding space, not input space
• JEPAs do not seek representations invariant to a set of hand-crafted data 
augmentations in contrast to Joint-Embedding Architectures

### [Page 22]
From SSL to Transferable Representations
• SSL for prediction usually assumes one target table
• Pre-train on unlabeled rows
• Fine-tune on labeled rows from the same dataset
• Transferable tabular representations relax this setting:
• Learn from unlabeled tables
• Adapt with few labels
• Transfer across different column structures
The challenge shifts from learning within one table 
to transferring across tasks or schemas
22



### [Page 23]
STUNT: Self-Generated Tasks
• Key Idea: Generate diverse pseudo-tasks from an unlabeled table
by treating the table’s column feature as a useful target
• Randomly select a subset of columns
• Cluster samples using the selected columns
• Use the cluster assignments as pseudo-labels
• Train a few-shot learner across the diverse "self-generated" tasks
23
Nam et al., STUNT: Few-shot Tabular Learning with Self-generated Tasks from Unlabeled Tables, ICLR 2023



### [Page 24]
STUNT: Self-Generated Tasks
• STUNT can adapt to a task with only a few labeled samples
• In such scenarios, supervised learning and SSL methods often fail because 
they do not have adaptation ability from few labeled samples
24
Nam et al., STUNT: Few-shot Tabular Learning with Self-generated Tasks from Unlabeled Tables, ICLR 2023



### [Page 25]
Transfer Across Different Table Schemas
• Problem: Most tabular models assume a fixed set of columns
• Training and test tables must share the same feature schema
• Different tables may have partially overlapping columns
25
Wang & Sun, TransTab: Learning Transferable Tabular Transformers Across Tables, NeurIPS 2022



### [Page 26]
Transfer Across Different Table Schemas
• Idea #1: Convert tabular data into "semantically-encoded" tokens
• Use the column description (e.g., column name) → transferrable
26
Wang & Sun, TransTab: Learning Transferable Tabular Transformers Across Tables, NeurIPS 2022



### [Page 27]
Transfer Across Different Table Schemas
• Idea #2: Represent each row as a graph of column names & values
• Each row becomes a star-shaped graphlet
• Different tables can be mapped into the same graph-based input format
• Learn contextual entity representations 
from external relational knowledge
27
Kim et al., CARTE: Pretraining and Transfer for Tabular Learning, 2024

### [Page 29]
Tabular Anomaly Detection
• Anomaly detection is often label-scarce
• Abnormal samples are rare and expensive to label
• Many settings only provide normal training data
• Focus on modeling what is normal, 
rather than directly classifying what is abnormal
• Normal samples should exhibit consistent patterns
• Anomalies should be distinguishable from normal samples in the learned 
representation space
Key Question
How can we learn normality without explicit anomaly labels?
29



### [Page 30]
Two Views of Normality Learning
• Reconstruction-based view
• Normal samples should be predictable from partial information
• Anomalies violate learned feature correlations
• Anomaly score: high reconstruction error
• Representation-based view
• Normal samples should lie close to a learned normal structure
• Anomalies deviate from the normal representation space
• Anomaly score: large distance from the normal manifold
30



### [Page 31]
ICL: Internal Contrastive Learning
• Key Idea: Learn normality by matching one part of a sample with 
the rest of the same sample
• Split each sample into a masked part and its complement
• Learn two mappings that maximize agreement between matching parts
• Use the contrastive loss itself as the anomaly score
31
Shenkar & Wolf, Anomaly Detection for Tabular Data with Internal Contrastive Learning, ICLR 2022
Anomaly score:
Contrastive loss



### [Page 32]
MCM: Masked Cell Modeling
• Key Idea: Learn normal feature correlations through masked cell 
reconstruction
• Mask cells in normal samples and reconstruct the original values
• Use a learnable mask generator instead of fixed random masks
• Generate multiple diverse masks to capture different normal correlations
32
Yin et al., MCM: Masked Cell Modeling for Anomaly Detection in Tabular Data, ICLR 2024
Anomaly score:
Average reconstruction error 
over multiple masked versions



### [Page 33]
NPT-AD: Beyond Individual Input
• Key Idea: Reconstruct masked features using both feature-feature 
and sample-sample dependencies
• Use NPT to combine Attention Between Attributes and Datapoints
• Train the model to reconstruct masked features of normal samples
• During inference, use the training set as context for reconstruction
33
Thimonier et al., Beyond Individual Input for Deep Anomaly Detection on Tabular Data, ICML 2024
Anomaly score:
Masked-feature reconstruction error



### [Page 34]
Disent-AD: Disentangling Features
• Key Idea: Normal tabular attributes can be divided into 
non-overlapping but correlated subsets
• Use two attention heads to extract different latent attribute subsets
• Reconstruct the original sample from each subset
• Normal samples should be recoverable from correlated subsets
• Anomalies disrupt the correlations that make such reconstruction possible
34
Ye et al., Disentangling Tabular Data Towards Better One-Class Anomaly Detection, AAAI 2025
Anomaly score:
reconstruction error



### [Page 35]
Decomposed Representation Learning
• Key Idea: Learn a constrained latent space in which normal 
representations can be decomposed using orthogonal basis vectors
• Encode each sample into a latent representation
• Represent normal samples as weighted sum of fixed orthogonal bases
35
Ye et al., DRL: Decomposed Representation Learning for Tabular Anomaly Detection, ICLR 2025
Anomaly score: decomposition error in representation space
